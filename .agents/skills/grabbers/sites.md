# Sites

Sites rebrand constantly; probe for a successor before declaring one dead, and don't guess slug patterns — get a real series URL from the site's own listing.

## Moved or unsupported

- **Moved, still supported**: tcbscans → tcbonepiecechapters; mangabat → mangabats; asuratoon → asurascans; genzupdates → genztoons.org; zonatmo.com → zonatmo.org (seized Apr 2026); aurorascans → qimanhwa → qimanga; mangalivre.tv/.net → mangalivre.to; mangabuddy → mangak.io; witchscans → witchtoons.net; mangapark.to/.io/.page → mangapark1.com → mangapark.cc; utoon.net (now a "site suspended" hijack page) → utoon.us; kaynscan.org → kaynscans.com (Aug 2026: the Astro/astro-island platform is gone, the new domain runs the same Next.js RSC platform as witchtoons.net — shared in `rsccomic.go` — and the old domain 301s over remapping `/series/{slug}` to `/series/comic/{slug}`, a rewrite the grabber also applies in code); elftoon.com → elftoon.net (same RSC platform, `/manga/{slug}` remapped to `/series/comic/{slug}` in code); mangaball.net → mangaball.com; baozimh.com → twmanga.com (mirror; baozimh.com 403s).
- **mangapark.cc** (Oct 2026; old hosts are dead or hijacked — .to redirects to AliExpress). Plain HTML, no browser. Series at `/manga/{slug}`, readers at `/read/{slug}/{lang}/chapter-N`. Chapters come from `GET /manga/{slug}/chapters?lang=LANG&offset=N` (HTML fragment) with a `<span class="chapter-batch-meta">` carrying `data-has-more`/`data-next-offset`/`data-total`; entries are `<li class="item" data-number="N">`, paginated until `data-has-more="false"`. Language defaults to EN (uppercase). `data-number=""` = one-shot. Reader images are in `section.chapter-reader img`, CDN-hosted, no Referer needed. Old-host URLs are rewritten in `mangaparkSeriesURL` without fetching.
- **witchtoons.net** deserves a note: the redirect from witchscans drops the path and the platform changed entirely, so old URLs can't be remapped. It's server-rendered Next.js, so no browser — but the chapter list is in the RSC payload, not the DOM (the series page renders exactly *one* chapter link, so a selector-driven grabber sees 1 of 61 and looks like it works), and is paginated at 100 per page. Page URLs are signed with a ~1h TTL, harmless since they download immediately.
- **bentomanga.com** and **mngaar.com** (Cloudflare "Just a moment…"): headless Chromium got the challenge page and never the series, and further runs escalate to a visible window on the user's desktop, so both are dropped until someone can test them with a visible browser the user allows.
- **leitor.net** (PT-BR, Oct 2026): not a reader. It is a directory of official sources (MangaPlus, Comikey, JBC, Toomics) whose "ler agora" links leave the site, so there are no chapters to download.
- **madaradex.org** (Oct 2026): a plain Madara site whose image CDN 403s without the `mdx_fp`/`mdx_auth` cookies its reader script mints through admin-ajax.php; `authorizeMadaradex` (`grabber/madaradex.go`) repeats that handshake from `PlainHTML.FetchChapter`, renewing it every 5 hours.
- **kuroimanga.com** (Turkish, Oct 2026): Madara, but the reader shows "Bu seriyi okumak için siteye üye olmalısınız" (members only) on every series tried, so nothing downloads without an account.
- **webtoontr.net** (Oct 2026): the series pages 403 intermittently, and the image CDN (`*.wdepo.top`) 301s every request to its homepage whatever the Referer, so no page is an image.
- **mangazin.org** (Oct 2026): a Madara copy of another site whose chapters point at images that mostly 404 on its own CDN (a few pages per chapter), plus hotlinked promo pages from the source site that 403. No chapter downloads whole.
- **kangaryu-team.fr** (Oct 2026): MangaReaderCMS like onma.top, but its only series lists images that all 404 (last updated 2021).
- **colamanga** (#30): app-gated reader on top of client-side image encryption. Not feasible.
- **comick.dev**: CF is beatable and the chapter-list JSON is reachable, but the page-image endpoint returns `[]` anonymously for every chapter tried, and the live reader receives no images either. Needs an account.
- **sakuramangas.org** (#90): the wall is client-side image decryption, **not** Cloudflare — two earlier investigations got this wrong. Pages exist only as `blob:`s their cipher decodes on genuine, dwelt human interaction; every automated recipe produced zero decoded images, and direct URLs 403 past the first few. Beating it properly means reverse-engineering rotating obfuscated keys, PoW headers and CSRF tokens — the stack that got the dedicated Tachiyomi extension delisted. Not worth it. Two techniques from it *are* reusable, though:
  - **CF clearance by attaching to a user-launched Chrome**: a Chrome the user starts with `--remote-debugging-port` (no debugger attached at challenge time) clears the challenge; chromedp then attaches via `NewRemoteAllocator` and reuses the cached `cf_clearance`, plus `BringToFront()` since attached tabs are backgrounded. It's our chromedp-*launched* Chrome that CF detects, not headed mode — so this is the move for "works in my Chrome, not in automated Chrome".
  - **CDP `Input.dispatch*Event` produces `isTrusted:true` events**, which drive reader gestures that a page's JS ignores from synthetic `dispatchEvent`/`.click()` calls.

## Per-grabber notes

- **asmotoon.com** (Oct 2026 redesign): series and chapters are both one path segment (`/{slug}`, `/{slug}-chapter-N`, no `/series/`), so a chapter URL finds its series through the reader's "Back to series" link. Visible window only. The site also hosts novels (series page "Type" box says NOVEL; text reader, no images), which the `Novel` selector refuses with a clear error. Paid rows carry a `[data-lock-chip]` coin chip and their reader serves no images logged out, so they are `Locked`. A manga's reader can start with a text credits page (`.reader-note`), which the `img.reader-page` selector skips. Smoke target: tadaima-taikichuu-nitsuki (chapters 17+ are paid).
- **MangaReaderCMS** (anzmanga25.com, onma.top, scan-vf.net, one `plainHTMLSelectors` entry): rows are `h5.chapter-title-rtl`, whose text may lead with the title ("Kagurabachi 134", "392 : ..."), so `NumberRe` reads the number from the `/manga/{slug}/{number}` URL. The series title sits in a different element per theme, and the pages are `data-src` (padded with spaces) in `#all`. A chapter URL finds its series through the parent-path fallback. The rows' download links go through an ad shortener (shrinkme) and are never taken.
- **oremanga.net** (Thai): the maid.my.id theme with `/series/{slug}/` pages and reader pages in `.reader-area-main`; chapter text is "ตอนที่ N" (`thaiChapterNumberRe`). `/{slug}/` alone is a paginated archive of chapter posts, not the series page. The site's meta description is 18+ boilerplate, but the series tried are mainstream.
- **Madara one-shots** (anikiga.com, Turkish): a row such as "One-shot" has no number, so `tcbChapterNumber` gives it the number in the last URL segment, else 0, instead of failing the whole listing. Unnumbered rows (Prologue, Epilogue, One-shot) therefore come out as chapter 0, or the number in their URL, so several can share 0 and are kept apart by the `v{{.Version}}` file suffix.
- **Guya instances** (hachirumi.com): `Guya.Test()` accepts the domains it knows and, for any other `/read/manga/{slug}` URL, probes `/api/series/{slug}/` for a feed with a slug and a chapters map.
- **`heavenmanga.go`** (heavenmanga.com, Spanish, Laravel with a Koneko reader): the series page renders no chapters. Its table is a DataTables server-side list that the same URL answers as JSON with `draw`, `columns`, `start` and `length=-1` (every row in one request, so no page boundary can shift a release between pages). Each row is one release, its reader ID is the row ID, and its uploader is the `span.greenSpan` label; the label "Solo Subida" means no group. The reader lists all its pages in a script as `"npage"`/`"imgURL"` pairs.
- **`lelscans.go`** (lelscans.net, French): the series dropdown is the chapter list. The reader serves one page per URL (`/scan-{slug}/{chapter}/{page}`), so FetchChapter fetches each page for its image, with the page count from the pager.
- **`mangaball.go`**: Turnstile challenges every HTML page (series, reader, homepage), for plain HTTP and browsers alike, but not `api.mangaball.com`: title JSON, `POST chapter/chapter-listing-by-title-id` and `POST chapter/detail {"chapter_id"}` (page URLs and `title_id`, used for chapter-URL input) are all plain HTTP. The image CDN answers a Cloudflare 403 without a `https://mangaball.com/` Referer (the downloader's default, so `.net` URLs are rewritten to `.com`). curl and python get 403 regardless (TLS fingerprint): test with Go.
- **`baozimh.go`** (包子漫画) is plain HTML but **geo-routed by visitor IP**: mainland-China IPs get simplified-script pages, everyone else traditional. Same markup either way, but the chapter-number regex must accept both `话`/`話` (a hardcoded one silently drops every chapter for half the world) and a bare leading number, while rejecting digit-led dates in code since RE2 has no lookahead. Long chapters span several reader pages linked by a "next page" link with overlapping images, merged and deduped by CDN URL. Repeated chapter *numbers* are often genuinely distinct files and all download. baozimh.com itself now 403s us, so the smoke target and README use the www.twmanga.com mirror (same grabber; `Test()` accepts both). Reader URLs (`/comic/chapter/<slug>/...`) are mapped to the series by `baozimhSeriesURL`.
- **`mangaplus.go`** (Manga Plus) talks to the **app API** (`jumpg-api.tokyo-cdn.com`), not the website's: that one serves a truncated chapter list and paywalls the middle of a running series. Responses are **protobuf**, read by `protobuf.go` (a minimal wire-format reader, no runtime or generated code). Every call needs the base params (`os`, `os_ver`, `app_ver`) and an **anonymous device `secret`**, registered with `PUT /register` and cached (0600) under the user config dir; `MANGAPLUS_SECRET` overrides it, and a cached one the API rejects is re-registered once. The complete list is `chapter_list_v2` (field 38) of `title_detailV3`; `chapter_list_group` (28) is only a fallback. Chapters are **not filtered by `chapter_type`** — one read for free flips to `STANDARD` and stays readable — only the API's refusal (11301/11302) is an error. `manga_viewer_v3` mints a `plus_vw_token` **per response**, bound to that response's signed image URLs and only present in its `Set-Cookie`, so the app API uses its own `net/http` client and the token travels as `Page.Headers` (`Plus-Vw-Token` plus an explicit `Cookie`), never the shared session; viewer responses are cached per chapter because `--bundle` fetches every chapter twice. The API **rate limits hard** (~10 calls in a few seconds is error 10522 and a 10+ minute lockout), so calls are spaced 500ms apart and the first 10522 makes every later call fail locally. Names aren't always numbers (`#001-1`, `ex`), so numbers are derived in order and kept strictly increasing: split parts go in the hundredths (`#001-1` is 1.01), unnumbered chapters get `previous + 0.1`. A `title_id` is **one edition per language**, each with its own chapter list (some list the whole run, others only the six-chapter free window), and `lang`/`clang` can't switch between them: `--language` looks the edition's id up in `title_languages` (field 27) and refetches its detail. `Chapter.Language` keeps the API's three-letter code (`eng`, `esp`), which is what `clang` sends.
- **nyraxmanga.com** (themesia): paid rows are `li.chapter-is-locked` with a `.plus-badge`, and their reader serves no images logged out, so its own `PlainHTML` entry (rows scoped to the site's host) sets `Locked`. The generic themesia entry doesn't.
- **manga.smuglo.li** (Lilyreader, FoOlSlide): the long series restart the chapter numbers in every volume, so one number matches a chapter per volume. The smoke target uses a short series with unique numbers.
- **noranofansub.com** (FoOlSlide): the reader's `img.page-N` placeholders are what lets `SeriesLink` fire, so a pasted chapter URL reaches its series instead of the site's latest-releases page.
