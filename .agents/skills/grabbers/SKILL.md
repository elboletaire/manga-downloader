Read this for any site or grabber work: adding, fixing, debugging, investigating or smoke-testing one. The reference files next to it hold the detail, listed at the end.

## Workflow

1. Triage the site first, as described in "Investigating a new site" below.
2. Pick the grabber kind from the "Then:" list there: a `PlainHTML` `SiteSelector`, a `BrowserSiteSelector`, or a dedicated grabber.
3. If the site lists several scanlation groups' releases of a chapter, follow the "Scanlation groups" bullet under "The grabber package" below.
4. Keep `Test()` markup-based, per the rule at the end of "Investigating a new site".
5. Add the smoke target, the README "Supported sites" table row (`| [domain](url) \* | notes | — |`, the `\*` only for browser sites; start it at `—`, or the date of your verified download; CI and `make site-status` keep the column current (a row with no smoke target stays `—` until one exists; the website shows new dates at the next daily Pages run); and bump both counts: the features-list bullet and "Show all N") and, for plain-HTTP grabbers, the CI matrix entry in `.github/workflows/smoke.yaml`.
6. Check whether the listing marks locked (paid, premium, early-access or members-only) chapters and, if so, set `Chapter.Locked` (see "Locked (paid) chapters" below).
7. Verify with `tools/verify-cbz` on the downloaded archives, not just the smoke target's exit code.

### Investigating a new site

Triage with curl first: fetch with a browser UA and check the `<title>`. "Just a moment…" means a CF JS challenge; TLS drops, empty SPA shells and encrypted-image readers are equally out for plain HTTP. But check the *content*, not just status/size — fanfox returns complete HTML yet swaps every series page for an age gate until an `isAdult=1` cookie is sent, and a 200 can be a parked or ransom page. 403/500 in the app but 200 in curl almost always means headers (`http/request.go` sends UA, Accept, Accept-Language and a trailing-slash referer, all because some site demanded them). Old chapters are often dropped from CDNs, so "chapter 1" is usually the worst test target. And a near-empty `grep '<img src="'` proves nothing — attributes may be single-quoted, and `grep -c` on minified HTML counts lines, not matches.

Then:

- Plain HTML → add a `SiteSelector` to `PlainHTML.Test()`, plus a `grabber/html` smoke target and a README table row.
- Needs a browser but selector-friendly → add a `BrowserSiteSelector` to `browserSelectors`.
- Otherwise → new grabber implementing `Site` (embed `*Grabber`), registered in `IdentifySite()`, with its own smoke target in the top-level `grabber:` aggregate (not `grabber/html`).

**Make `Test()` recognise the platform by its markup, not the site by its domain.** Sites get cloned and rebranded constantly, and a domain regex turns away every clone our code could already download: that's why six sites worked with zero code (themesia markup for `PlainHTML`, Madara's `ajax/chapters` for the domain-agnostic `tcb`), while each new TanStack or RSC-comic domain needed its own wrapper grabber (`azorafly.go` is ~20 lines that only say "this domain is TanStack"). For a new grabber that targets a platform rather than one service, fingerprint the fetched page with something specific (e.g. TanStack's `initialChapters:$R[` + `totalChapterCount`), place it among the fetch-testing grabbers, and keep a domain only for URL rewrites a site genuinely needs (kaynscan's `/series/{slug}` → `/series/comic/{slug}`). Domain matching is still right for browser-gated sites (a browser is too expensive to start just to identify a page) and for single-service API grabbers (mangadex, mangaplus, webtoons). The existing domain-matched platform grabbers (`tanstackComic`, `rscComic`, the manganelo and mangahere families) predate this rule and haven't been converted; do it, with a shared page fetch so the structural tests don't each GET the URL, as a deliberate refactor rather than in passing.

## The grabber package

- `Site` (`grabber/site.go`) is the contract: `Test`, `FetchTitle`, `FetchChapters`, `FetchChapter`, … The base `Grabber` provides shared settings/helpers.
- `Filterable`/`Filterables` (`filterable.go`) abstracts chapters for sorting/filtering by number; each grabber has its own chapter struct embedding `grabber.Chapter`.
- **Chapter URL resolution**: a pasted chapter link must load the whole series. Dedicated grabbers do it in a `resolveSeriesURL()` called from `FetchTitle()`/`FetchChapters()`: a no-op for series URLs, deriving the series from the URL before fetching (at most once), matching on the path so `www.`, case, query and fragment don't matter, returning `errSeriesNotFound` when it gives up, with a table test per rewrite. Mobile hosts are rewritten to the desktop one in `Test()` (mangatown, mangahere, fanfox). `PlainHTML` resolves reader pages as a last resort, after every grabber has declined in `IdentifySite()`: a selector's `SeriesLink` (the reader's back-to-series link, applied only when that selector's `Image` matches the page), then breadcrumbs and parent paths, at most 3 fetches; `FollowSeriesLink` follows it even when the reader shows a partial chapter dropdown. `WordPressCategory` and `Blogger` are matched by markup only after that fallback, since themesia chapter pages are WordPress posts too.
- **`PlainHTML`** (`plainhtml.go`): generic goquery scraper driven by a list of `SiteSelector` entries. `Paginated` walks the listing's `?page=N` pages until one has no rows (lelscanfr). Order in that list matters — a loose entry shadows later ones. `getPlainHTMLImageURL` handles readers that don't just expose `<img src>` (see `patterns.md`).
- **`PlainHTML.Test()` declines** when the first matching entry's rows can't be numbered: `rowChapterNumber` (shared with `FetchChapters`, URL fallback included) decides, so a domain-agnostic fallback like `tcb` takes Madara sites a loose entry would otherwise claim with zero chapters.
- **`PlainHTMLBrowser`** (`plainhtmlbrowser.go`): same selector parsing, but matches **by domain** (`browserSelectors`, no fetch — starting a browser is expensive) and renders through Chrome. Registered first in `IdentifySite()`. Browser selectors set `SeriesPathDepth`, so `PlainHTMLBrowser.Test()` trims a chapter path back to the series before rendering — the one exception to "resolve in Fetch*, not Test"; when depth can't resolve (chapter and series paths share no prefix), a `SeriesLink` on the entry follows the reader's back-to-series link instead.
- **Scanlation groups (`--scanlator`)**: for a listing with several groups' releases of one chapter:
  - **Normal case**: `FetchChapters` calls `Chapter.SetGroups` with the group names (none when the site doesn't say; it fills `Group` too, and keeps a name holding `", "` whole) and sets `Chapter.ID` (the release's own identifier), one chapter per release. `FetchChapter` downloads that specific release from `ID` and keeps both the group and the ID on the chapter it returns (copy them from the listed chapter).
  - **Don't** filter by group, tag the title, or dedupe. `core.Open` applies `--scanlator` to the listing (`grabber.SelectGroup`; default and `all` keep everything), and the group tag and `{{.Group}}` come from the field.
  - **One group per request**: a site that can only list one group per request implements `ScanlatorLister` and filters in `FetchChapters` through `SelectGroup` (see `grabber/filteroptions.go`).
  - **Cached listings**: add `Refilterable` when the chapter list is served from a cache on a second call, so another language doesn't re-walk the site (the app caches the listing per language itself, so a group change never refetches).
  - **`PlainHTML` multi-upload rows**: a `SiteSelector` whose chapter row lists several uploads sets `Uploads` (a selector for each upload's sub-row), `UploadLink` and `UploadGroup` (both searched inside the sub-row; `UploadGroup` must match a single upload's group) and optionally `IDRe` (its first capture of the upload URL becomes `Chapter.ID`). Each sub-row becomes its own chapter, and a row with no link in any sub-row falls back to its own link (zonatmo).
  - **Default `ID`**: without `IDRe`, every `PlainHTML`/`PlainHTMLBrowser` chapter's `ID` is its URL's path and query (`ChapterQuery` excluded).
- **Locked chapters**: when the listing says a chapter is locked (coins, premium, early access, members-only), `FetchChapters` sets `Chapter.Locked` on it. The CLI and app leave locked chapters out before downloading (`core.SplitLocked`; the app won't select them), and `core.Download` still fails one with `core.ErrLocked` unfetched as a safety net. Set it only for chapters a logged-out reader can't open, from a flag the listing states, as `tanstackComic` does from `isLocked` (a short-link lock is left out: no live example to check): an early-access chapter whose timer ran out and is free now must not be flagged. A reader with no images proves nothing, and `mangaplus`'s `locked()` is a guess, so neither sets it. Adding a site includes checking whether its listing marks paid chapters. For a `PlainHTML` entry, `SiteSelector.Locked` is a selector searched inside each row (a match locks it: lock icon, coin badge), and `LockedIsland` a func over the series page's Astro island props for sites that state it only there (asurascans, sanascans); rows are matched by chapter number.
- **`Test()` should decide from the URL alone, not fetch.** When a fetch is genuinely needed (as in `PlainHTML` and `tcb`), set `DisableRetry: true` on that request so an unrecognised or unreachable site fails immediately instead of burning retry attempts.
- **Rate-limited image servers**: a grabber can override `GetMaxConcurrency()` to cap (never raise) the user's concurrency, and implement `PagePacer` (`WaitPage()`, called by `downloader.FetchChapter` before every page request, retries included) to space requests out. Concurrency alone doesn't bound the rate: cached images come back in ~50ms. `mangadex` does both, after its MD@Home Cloudflare front started answering 429 (error 1015, `Retry-After` up to 60s) at about 1000 requests a minute. 429s on pages are retried after the server's `Retry-After` (`downloader.retryWait`).
- **Origins that fail pages at random**: a site whose image origin answers 404 or 5xx on a share of uncached requests (a CDN may then cache the 404 for hours) opts in by adding its host to `retryFlakyHosts` (`grabber/site.go`), which sets `Page.RetryFlaky`. Such a page is retried at least 6 times, 1s apart, each with a unique `retry=` query appended to the raw URL (so it reaches the origin); 429 keeps its Retry-After handling and every other site keeps its normal retries. `--retry 0` still disables it. Confirm first: repeat one URL with a throwaway query and see the mix of 200s and failures (for a cached 404, `cf-cache-status: HIT`).
- **The two selector lists are the source of truth for which sites are covered** — they drift constantly, so read them rather than any list in these guides.
- Dedicated grabbers exist where selectors can't work: `inmanga`, `mangadex` (API-based, language-aware), `manganelo` (mangabats + mangakakalot + natomanga + manganato.gg: the DOM renders only the newest 50 chapters, the full list comes from a paginated JSON API), `mangafire` (browser-driven, see `browser.md`), `mangak`, `qimanga`, `tcb` (Madara), `leercapitulo`, `witchtoons`, `teamshadowi`, `baozimh`, `atsumaru`, `mkissa`, `fanfox`, `mangatown` (the mangahere family without chapterfun.ashx: one HTML document per reader page, count from `total_pages`; m. host and chapter URLs are rewritten to the www series URL), `webtoons` (episode list from the m.webtoons.com `/api/v1/{webtoon|canvas}/{titleNo}/episodes` cursor API with pageSize=1000, HTML list walk as fallback; canvas ids only answer on the canvas route; the image CDN 403s without a webtoons.com Referer; free episodes only, since locked ones aren't listed on the web), and others.

The baozimh and Manga Plus notes live in `sites.md`, under "Per-grabber notes".

## Reference files

- `patterns.md`: reader patterns for images that aren't plain `<img src>` (`ts_reader`, FoOlSlide, `${uid}` templates, TanStack/seroval, Next.js RSC, P.A.C.K.E.R., infinite-scroll readers). Read when a reader's images aren't in the HTML.
- `browser.md`: the `browser` package (chromedp, Cloudflare clearance, the challenge clicker, container flags, `tools/probe`). Read before writing a browser-driven grabber or when a site is Cloudflare-gated.
- `rules.md`: hard-won rules on paywalls, chapter lists, titles, selector scoping and CBZ verification. Read before writing selectors, when a chapter list looks short or stops at a round number, when a run "succeeds" with bad archives, or when a browser wait selector passes too early.
- `sites.md`: sites that moved, or that we deliberately don't support, plus per-grabber notes (`baozimh`, `mangaplus`). Read when a site stops working or before starting on a requested site.
