# The browser package

`browser/browser.go` drives a locally-installed Chromium-family browser (found by `browser/find.go`: chromedp's own candidates first, then Brave and Edge; `MANGA_DOWNLOADER_BROWSER=/abs/path` overrides the search) for sites plain HTTP can't scrape. One process, started lazily and reused. `GetHTML` returns rendered HTML and harvests cookies + UA into `http/session.go`, so images still download over fast plain HTTP reusing the browser's Cloudflare clearance. Variants: `GetHTMLWithScroll` (steps a `Scroll.Container` a viewport at a time until its `Done` JS holds or the bottom: readers that scroll an inner element ignore `window.scrollTo`, and bigger jumps skip lazy pages; `Scroll.Init` runs JS in the document before the page's own scripts, for that navigation only, e.g. to seed a reader's localStorage setting that mounts every page up front, so `Done` holds without scrolling), `GetReaderHTML`, `GetAPIResponses`. Some image hosts 403 any request with a Referer (the reader's `<img referrerpolicy="no-referrer">` gives it away): set `Page.NoReferer`.

- **Lifecycle (`browser/lifecycle.go`).** Every page operation goes through `runPage`: it starts the browser if needed (replacing one whose window was closed or that crashed: chromedp cancels its context when the connection drops, and a closed tab shows as a `TargetDestroyed` event), and **closes it after any failure**, so the next request starts fresh instead of reusing a dead or stuck one. This is deliberate: a failed browser is always discarded, at the cost of passing a Cloudflare check again (clearance and the visible window go with it), since reusing one that had failed is exactly what broke later loads. A host that escalated to a visible window is remembered for the rest of the process (`browser/visible.go`), so its later starts skip the headless probe even after the browser was closed; a visible start that fails (no display) isn't remembered. `Close` cancels the running load first (`ErrClosed`), and the loads queued behind it too (`lock` reads the abort context before waiting), so quitting never waits behind a 5-minute challenge or restarts the browser, and the GUI also closes the browser after each download, when the URL box is cleared (`Controller.Clear`), and after `SetIdleTimeout` (2 minutes) unused, which `Hold` suspends during a download. `Close` also kills a browser that's still starting. The CLI closes it on Ctrl+C or SIGTERM (`cmd/interrupt.go`, exiting 130/143, muting output so aborted loads print no errors; a second Ctrl+C kills at once).
- **Processes on Windows (`browser/proc_windows.go`).** chromedp only kills the main browser process, and nothing kills it if the app dies first, so the browser goes into a kill-on-close job object (its later children join it) and `release` kills the helpers it started before that (by parent pid, holding handles and checking creation times so a reused pid is never hit). Only Linux has chromedp's `Pdeathsig`; on macOS an app that crashes or is killed can leave the browser running.
- **Headless no longer leaks into plain HTTP.** `hideHeadless` strips `HeadlessChrome` from the browser's user agent and client-hint brands (read from `chrome://version`, since `about:blank` isn't a secure context and an override without metadata empties them): `harvestSession` copies it into `http`, and it used to make every later request (other sites included) go out as HeadlessChrome and get 403s until the app restarted.
- **Progress notices come from the browser package**, not the grabbers: starting the browser, a periodic "waiting for <host>" until the page renders (ops call `hooks.rendered`, so scrolling and pagination after that stay quiet; `render` also re-arms the timeout there, so only a timeout before the wait selector matched counts as a challenge), the escalation and the reset. So every path that renders a page (chapter-to-series resolution included) reports itself without extra code.
- **Real-browser tests** (`browser/lifecycle_integration_test.go`) run with `MANGA_DOWNLOADER_BROWSER_TESTS=1` on Linux against a local server, headless only (`headlessOnly` refuses visible launches whatever the display): a timed-out load followed by a working one, a killed browser, the harvested user agent, `Close` mid-load. The rest of the lifecycle has unit tests with a fake `launch`.
- **Always try the site's own API/HTTP first.** mangafire's API was wide open until it started signing calls with a CF-gated `vrf` token (403 "Missing token"), forcing a browser; zonatmo went the other way and dropped its TLS block. Re-verify instead of assuming either direction is permanent.
- **Headless loses to Cloudflare; headed usually wins.** `GetHTML` handles this: a short headless probe, then a teardown and reopen as visible on `challengeError`. A site that never passes headless (a captcha of its own) declares it from its grabber with `func init() { browser.RequireVisible("example.com") }` (host and subdomains), which skips the probe; `NeedsVisible(url)` reports either case, and the GUI shows it on the *Show the browser window* switch. `--browser-visible` forces a window for every site and is rarely needed.
- **"The browser needs you".** A window opened because the site needs one (declared, remembered or escalated) raises an `Attention` through `SetAttentionHandler` and is brought to the front (`Page.bringToFront`, after restoring a minimized window; Windows may refuse the focus). Later loads in an open window (whatever opened it) raise it only once they're slow to render (the first "waiting" notice), and only for a site that needs the window. It ends when the page renders (`hooks.rendered`) or the load ends however it does. The CLI prints `Attention.Message()` as a bright yellow line; the app shows it over the window with *Show the browser window* (`BringToFront`) and *Dismiss*. A window the user asked for raises nothing at start, and nothing at all for sites that don't need one.
- **Interactive "Verify you are human" checkboxes are auto-clicked.** Whenever the browser is headed, `startChallengeClicker` polls in the background and CDP-clicks the Turnstile checkbox (the widget's an unqueryable closed shadow root, so it targets the full-width ~68px host row in `div.main-content`; CDP mouse events are `isTrusted:true`, which Turnstile accepts). This is what lets the docker `:browser` image — whose "visible" window is an unattended Xvfb framebuffer — pass interactive challenges, not just managed ones.
- **Running in a container needs `--no-sandbox` + a writable HOME.** `start()` adds `chromedp.NoSandbox` when `inContainer()` (detects `/.dockerenv`, `/run/.containerenv`, or `BROWSER_NO_SANDBOX=1`) — chrome's setuid/userns sandbox can't init in an unprivileged container. Alpine chromium also dies with a misleading `chrome_crashpad_handler: --database is required` when `$HOME` isn't writable; `entrypoint.sh` (shared by both images) creates `/home/manga` for the runtime user, which the Manga Plus secret cache needs too. See `docker/Dockerfile.browser` (chromium + xvfb + CJK fonts) and `docker/entrypoint-browser.sh` (Xvfb `:99` wrapper).
- **A theme tells you nothing about the hosting.** The same themesia or Madara markup is plain HTTP on one domain and CF-gated on another — check, don't assume.
- **`tools/probe`** renders a URL and tests selectors. Env knobs: `PROBE_VISIBLE=1`, `PROBE_TIMEOUT=4m` (default 45s), `PROBE_SLEEP=8s` (settle for lazy SPAs), `PROBE_DUMP=/tmp/x.html`, `PROBE_NETLOG=1` (log non-asset responses — how mangafire's API was found), `PROBE_SCROLL=1` + `PROBE_SCROLL_IN`/`PROBE_SCROLL_DONE` (scroll a lazy reader), `PROBE_FETCH_SEL` (test a plain-HTTP image download with the harvested session), `PROBE_API_URL` + `PROBE_API_DUMP_DIR` (fetch JSON APIs reusing the session; checks cookie carry-over to e.g. an `api.` subdomain).
