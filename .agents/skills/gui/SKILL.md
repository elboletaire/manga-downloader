# The GUI (`gui/`)

The desktop app is a [Wails v2](https://wails.io) app in its own Go module (`gui/`, `go.mod` requiring `github.com/wailsapp/wails/v2`), so the CLI's `go.mod` never pulls the webview. Wails shows a React + TypeScript frontend (`gui/frontend/`, pnpm, vite, vitest) in the system's webview: WebKitGTK on Linux, WebView2 on Windows, WKWebView on macOS. Why Wails over Fyne: native file dialogs, a webview UI, and Windows builds that need no cgo, so they cross-compile from any host. Linux still needs cgo and the WebKitGTK headers.

- **Built by `release-gui.yaml`** through `make build/gui/<os>` (`wails build`, on native Linux runners for amd64 and arm64, a Linux runner for both Windows archs, and macOS for the universal bundle). Windows arm64 gets a native arm64 build, cross-compiled on Linux. Each Windows arch also ships an NSIS installer (`-nsis`, `gui/build/windows/installer/project.nsi`, committed; `wails_tools.nsh` is regenerated and gitignored) as `manga-downloader-gui-$TAG-windows-$GOARCH-installer.exe` next to the zip: scope picked at run time: elevated is per machine (`C:\Program Files\Manga Downloader`, HKLM), otherwise per user (`%LOCALAPPDATA%\Programs\Manga Downloader`, HKCU), and a non-elevated run with a per-machine install relaunches itself elevated; uninstall key `Manga Downloader` (SHCTX), `/relaunch` starts the app after installing. The makefile is the source of truth for every build and test (its comments list the variables): `make build/gui` is the plain host build the screenshots use, `make build/gui/<os>` the release's, and `make test/gui` what `gui-test.yaml` runs; `make build`/`make test` leave the GUI out, as `./...` stops at the nested module.
- **Linux tarball**: `packaging/linux/` holds `install.sh` (per-user install into `~/.local`: binary, hicolor 256x256 icon, a `.desktop` with the binary's absolute `Exec=`; `--uninstall` removes them) and the `.desktop` template the release copies in. `test-install.sh` exercises it in a throwaway HOME: `gui-test.yaml` against a stub binary on every PR, and `release-gui.yaml` against the staged release before packing. The desktop file id matches GTK's prgname (`manga-downloader-gui`), so keep the binary's name and the `.desktop` name in step.
- **Build tags**: `desktop,production` (without `production` Wails refuses to start: it selects the real app instead of a stub), `nodynamic` (the AVIF decoder, see "Page conversion" in `AGENTS.md`), and `webkit2_41` on Linux (current distros only ship WebKitGTK 4.1).
- **The seam is `core` + `notice`**, as for the CLI. `controller.go` is toolkit-free: the state, the selection, the run and the log. `app.go` is the bound `App`, a thin adapter that turns the controller into DTOs, pushes them to the window, and does the OS-specific bits (the folder picker, opening the folder). Keep logic in the controller so it's testable without a window.
- **Pushes are throttled**: `App.notify` (`app.go`, the controller's change signal, called from any goroutine) signals a one-slot channel, and one goroutine emits `state` at most every 100ms, always sending the last change. `selection` and `log` are sent only when their generation counter moved, since they can be thousands of entries. `chapters` is sent once per load. The window also calls `State()`, `Chapters()`, `Selection()` and `Log()` on mount, because events emitted before the listener registers are lost. Nothing is emitted before `OnStartup` or after `OnShutdown`.
- **The frontend talks to the backend only through `gui/frontend/src/api.ts`**, which wraps the generated `wailsjs/` bindings. `mock.ts` implements the same `Api` in memory: `pnpm dev` (or `?mock&scenario=…`, with the scenarios listed in the header of `mock.ts`) runs the UI in a plain browser without the Go app. The design pass works against it. The bindings are committed (`-skipbindings` in the release) and regenerated with `wails generate module` in an environment with the webview headers; keep `wails.json`'s `wailsjsdir` at `./frontend`, which makes the output `frontend/wailsjs/`. Change `api.ts`'s types with `types.ts` and the Go DTOs together.
- **The README and website screenshots come from `tools/screenshots/`** (macOS: `capture-all.sh --install` retakes every shot from the mock; see its README). Adding or changing a scenario that a screenshot shows means updating its shot list there; the mock is only bundled with `VITE_MOCK=1` or in dev.
- **The language and scanlator filters are selectors once a series loads**, built from the site's `FilterOptions` (`Controller.Filters`, shown as `State.languages`/`scanlators`, null when the site lists none). Picking one applies at once: the controller's `ConfigureLoad` (`SetOptionsAndLoad`, via `optionsWriter.patch(patch, url)`) sets the filter and starts the load in one step, so the window never shows it as not applied (`Stale` is for typed values, until a reload). A value the series lacks falls back to `all`, the site's `Current` value, or no filter (`dropUnmatchedFilters`), and that fallback is saved too. A site that lists no languages can't be checked against them, so a language that matched nothing (a `NoChaptersError`) is dropped for that load only: the reload gets a copy of the settings with it cleared, the saved language stays (and is still saved), and the field shows cleared and disabled. The drop only happens when no scanlator filter could have caused the empty list (none typed, or one the site lists); a network failure keeps it.
- **The browser's window follows the site.** `State.browserVisibleAuto` (`browser.NeedsVisible` for the loaded URL: declared by the grabber, or escalated earlier this session) shows *Show the browser window* on and locked with a hint (`browserVisible.ts`), without touching the saved option. `State.browserAlert` is the browser's `Attention` message while its window may need the user; `BrowserAlert.tsx` shows it over the window, with `ShowBrowser` and `DismissBrowserAlert`, until the page renders or the load ends.
- **Options live in `gui.json`** in `os.UserConfigDir()/manga-downloader/` (0600, written atomically), next to the Manga Plus secret. Missing keys keep their defaults; a file that doesn't parse is a warning, not a failure.
- **Options and Settings are separate.** Options are what the CLI has a flag for, saved as gui.json's options and shown in the Options panel. Settings are the app-only preferences the CLI has no flag for (`uiLanguage`, `checkUpdates`, `simpleStart`), opened from the gear at the far right of the header's top row, or Ctrl+, / ⌘, (`.settings-btn`; `SettingsDialog.tsx`, the shortcut in `settingsShortcut.ts`). Closing it returns focus to the gear. They're `PrefsDTO` (`store.go`), kept on the controller outside `grabber.Settings` and pushed as `State.prefs`. The dialog applies each control at once, with no Save. `SetUILanguage`, `SetCheckUpdates` and `SetSimpleStart` are never refused while busy and leave Settings alone. `save()` writes gui.json's options and prefs together under `saveMu`, so any setter's save keeps the other half.
- **The simple start view** (`simpleStart`, on by default, GUI-only): an empty window shows the logo over the URL box and a Settings button, with the status bar kept, bare, for the log and the update badge (`startView.ts`). While nothing is loaded the view follows the pref at once (off: a glide to the full view; on: instant back to simple), and once a load starts it switches to the full view for good. The source bar is the same component in both, so the typed URL, the auto-load and the focus carry over; the logo, the URL form and the gear glide into place FLIP style (`flip.ts`, `data-flip`), the rest slides in (`.app.revealing`, timed by the `--glide` token), and it's instant under reduced motion. `&nosimple` turns it off in the mock.
- **Pack as is one choice of four** (chapters, merged, volumes, one file), saved as `packAs` and mapped onto the CLI's `Bundle` and `Volumes` (`store.go`); a `gui.json` with only the old `bundle` key migrates. The Volumes box isn't an option: it's per load, starts empty (the site's own volumes, offered as ranges when they can be written so), and is what a volume run packs (see "Volumes" in `AGENTS.md`). Merged is `--volumes parts`, with no box: the list heads each chapter with parts over them (`groupParts`/`partRows` in `volumes.ts`, by number, group and language as core merges them), and a chapter without parts stays a plain row.
- **Convert images is two checkboxes** in the window, mapped to the one setting (`avif`, `avif,webp`, `webp`, `none`, see `convertImages.ts`). The setting itself is still the CLI's string, so any of the four loads. With EPUB the AVIF box shows ticked and disabled (`avifSwitchOf`) without touching the saved value, and the Reading direction control appears only for EPUB.
- **The update check runs on release builds only** (`Tag` set, `gui/update.go`, toolkit-free): once at startup, in the background, it asks GitHub's `releases/latest` and reports a newer release through `State.update`. A failed check goes to stderr only, never the window's log, and is cancelled at shutdown. It's gated by the `checkUpdates` pref (`shouldCheckUpdates`), and turning that pref on runs it again (`SetCheckUpdates`), so a failed check can be retried. Dev builds make no request. The status bar's "!" is always yellow (`--warning-solid`), whatever the bump, and links to the latest release.
- **One-click update is for installed copies of the app on Windows, Linux and macOS** (the CLI updates through Homebrew or the zips; each OS has an `installer_<os>.go` supplying `packageName`, `installedCopy` and `runInstaller`, and `installer_other.go` stubs the rest). `State.update.oneClick` needs an installed copy, the platform's package on the release (`manga-downloader-gui-<tag>-windows-<arch>-installer.exe`, `...-linux-<arch>.tar.gz`, `...-darwin-universal.zip`) and `manga-downloader-gui-<tag>-SHA256SUMS.txt`, which the last job of `release-gui.yaml` publishes for every GUI asset. `App.Update` downloads the checksums and the package from the pinned release URL prefix into a temp dir (size checked against the API, SHA-256 against the checksums; a mismatch or missing entry refuses), then `runInstaller` takes over and the app quits. Windows: installed = the uninstall key's `InstallLocation` (HKCU first, then HKLM's 64-bit view; `detectScope`, which remembers the scope) equals the exe's folder, or an `uninstall.exe` sits next to it; the installer runs with `/relaunch` through ShellExecute, `runas` for a per-machine install (UAC; `os/exec` can't elevate) and `open` for a per-user one. Linux: installed = the running exe, symlinks resolved, is `~/.local/bin/manga-downloader-gui`; the tarball is unpacked safely (`extractTarGz`: only files and folders, names inside the folder), its `install.sh` runs (it swaps the binary by rename, so the running one isn't written to) and the new binary is started again detached (`setsid`, after a second). macOS: installed = the exe, symlinks resolved, is `Contents/MacOS/manga-downloader-gui` of an `.app` whose folder and bundle this user can write (`userCanWrite`, which also fails on a read-only mounted DMG), not under `/AppTranslocation/` and not while a Homebrew cask of the app is installed (`caskroomDirs`, since `brew upgrade` owns that copy). `installBundle` first removes the `.<App>.new-*`/`.<App>.old-*` directories an interrupted swap left, then unpacks the zip with `ditto -x -k` and refuses it unless the executable is a regular file, `Info.plist` names the bundle id and the bundle holds no symlink at all; it copies the app with `ditto` beside the installed one (a rename can't cross volumes), swaps the two by renames (old aside, new in, back on failure, naming the old path if that fails too), drops the quarantine attribute and `reopen` starts `open -n` after a second. Failures are logged and the release link stays. Keep the asset names in step with the workflow.
- **The window opens in the system's theme**: `theme_*.go` per OS picks the window's first background colour from the system theme, with a lookup bounded to 500ms on Linux and macOS (`gsettings`, `defaults`; the registry on Windows). `theme_test.go` ties both colours to `--bg` in `frontend/src/styles.css`, so a designer changing `--bg` must update `theme.go` too. `golang.org/x/sys` is a direct dependency for the Windows registry lookup.
- **The CLI launches it**: `manga-downloader ui` starts `manga-downloader-gui` from next to the CLI (or `Manga Downloader.app` next to it on macOS, or PATH), detached. Wails names the bundle after `wails.json`'s `name`, which is what `cmd/launcher.go` checks. On Windows, a bare run that Explorer started (the only process on its console, `cmd/console_windows.go`) does the same; without the GUI it shows help and waits for Enter so the window doesn't vanish.
- **Brand sources are in `assets/brand/`** (`brand.md` has the palette and the mapping to the GUI tokens). The GUI's mascot and header wordmark and the README header read the SVGs directly, and the app icons live in `gui/build/` (the `appicon.png`, `windows/icon.ico` and `linux/icon.png` the release packages), with `assets/brand/app/appicon.svg` as their source. Soft is the default face; Happy is only for a run that saved everything and the empty state, never a failure. Below 48px use the `-small` artwork, where Happy is the same as Soft.
- **Translations are in `gui/frontend/src/i18n/` and `src/locales/<lang>/<namespace>.json`** (en, es, ca; no runtime dependency). The namespaces are the files: app, source, filters, chapters, volumes, options, download, activity, summary, job, log, update, browser, errors, count, common, settings. `useI18n()` gives `t`, `lang`, `pref` and `setLanguage`, and is English outside an `I18nProvider`; `<T k values components />` renders rich text with `<code>`, `<em>`, `<kbd>` and `<strong>` only (no HTML), and a caller can pass its own components for the tags (SettingsDialog's author and license links). Keys are `namespace.area.item` in camelCase, `t()`'s key is always a string literal, plurals are `key_one`/`key_other` picked by `count`, and `{{name}}` placeholders stay as they are. English values must match the literals they replace, and `locales.test.ts` keeps es and ca in step with en (same keys, placeholders and tags).
- **The frontend translates; Go sends Messages.** Go never formats for the window. It sends a `Message` (`gui/msg.go`: `Key`, `Args`, and `Text`, the English rendering for logs and for keys the window lacks), either as `msg` or wrapped in an error by `uiErr`. `windowError` is the Wails `ErrorFormatter` (`main.go`) and returns a message error as its JSON string: Wails builds the window's `Error` from that value, and an object would arrive as "[object Object]". `errorMessage(e, t)` (`format.ts`) parses it back, and `say(t, msg, text)` (`i18n/index.ts`) renders the Messages that arrive in State (log lines, job rows, alerts).
- **What stays English**: CLI output and anything from core, grabber, packer, ranges or browser, errors and notices included; file names; the chapter and part labels in the list, which match the file names. Headers the window builds itself ("Chapter {{number}}", "Volume {{n}}", "{{count}} parts") are translated. Also never translated: "Manga Downloader", CBZ, EPUB, AVIF, WebP, JPEG, template tokens and range examples.
- **Glossary** (es / ca), matching `website/locales/*.json`: chapter capítulo/capítol · volume volumen/volum · file archivo/fitxer · bundle paquete/paquet · site sitio/lloc · download descargar/descarregar · folder carpeta/carpeta · scanlation group grupo de scanlation / grup de scanlation (scanlation is never translated) · merged unidos/units (the Pack-as label).
- **`?lang=` in the mock and the screenshots**: `?lang=en|es|ca|system` starts the mock window in that language (`system` follows the browser's), and without it the window is English, so dev and screenshots stay English. `SHOT_LANG` in `tools/screenshots/capture-all.sh` sets it for every shot.
