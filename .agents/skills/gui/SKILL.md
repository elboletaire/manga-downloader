# The GUI (`gui/`)

The desktop app is a [Wails v2](https://wails.io) app in its own Go module (`gui/`, `go.mod` requiring `github.com/wailsapp/wails/v2`), so the CLI's `go.mod` never pulls the webview and `go install …@latest` stays light. Wails shows a React + TypeScript frontend (`gui/frontend/`, pnpm, vite, vitest) in the system's webview: WebKitGTK on Linux, WebView2 on Windows, WKWebView on macOS. Why Wails over Fyne: native file dialogs, a webview UI, and Windows builds that need no cgo, so they cross-compile from any host. Linux still needs cgo and the WebKitGTK headers.

- **Built by `release-gui.yaml`** (`wails build`, on native Linux runners for amd64 and arm64, a Linux runner for both Windows archs, and macOS for the universal bundle). Windows arm64 gets a native arm64 build, cross-compiled on Linux. Locally, `make build/gui` builds for the host (it needs the webview headers on Linux), and `make build/gui/windows` cross-compiles the exe with `CGO_ENABLED=0`. `make test/gui` runs the Go tests and vitest; `make build`/`make test` leave the GUI out, as `./...` stops at the nested module.
- **Linux tarball**: `packaging/linux/` holds `install.sh` (per-user install into `~/.local`: binary, hicolor 256x256 icon, a `.desktop` with the binary's absolute `Exec=`; `--uninstall` removes them) and the `.desktop` template the release copies in. `test-install.sh` exercises it in a throwaway HOME: `gui-test.yaml` against a stub binary on every PR, and `release-gui.yaml` against the staged release before packing. The desktop file id matches GTK's prgname (`manga-downloader-gui`), so keep the binary's name and the `.desktop` name in step.
- **Build tags**: `desktop,production` (without `production` Wails refuses to start: it selects the real app instead of a stub), `nodynamic` (the AVIF decoder, see "Page conversion" in `AGENTS.md`), and `webkit2_41` on Linux (current distros only ship WebKitGTK 4.1). The release build is `wails build`; the makefile uses plain `go build`, so only the release gets the icon and manifest embedded into the Windows exe.
- **The seam is `core` + `notice`**, as for the CLI. `controller.go` is toolkit-free: the state, the selection, the run and the log. `app.go` is the bound `App`, a thin adapter that turns the controller into DTOs, pushes them to the window, and does the OS-specific bits (the folder picker, opening the folder). Keep logic in the controller so it's testable without a window.
- **Pushes are throttled**: `App.notify` (`app.go`, the controller's change signal, called from any goroutine) signals a one-slot channel, and one goroutine emits `state` at most every 100ms, always sending the last change. `selection` and `log` are sent only when their generation counter moved, since they can be thousands of entries. `chapters` is sent once per load. The window also calls `State()`, `Chapters()`, `Selection()` and `Log()` on mount, because events emitted before the listener registers are lost. Nothing is emitted before `OnStartup` or after `OnShutdown`.
- **The frontend talks to the backend only through `gui/frontend/src/api.ts`**, which wraps the generated `wailsjs/` bindings. `mock.ts` implements the same `Api` in memory: `pnpm dev` (or `?mock&scenario=…`, with the scenarios listed in the header of `mock.ts`) runs the UI in a plain browser without the Go app. The design pass works against it. The bindings are committed (`-skipbindings` in the release) and regenerated with `wails generate module` in an environment with the webview headers; keep `wails.json`'s `wailsjsdir` at `./frontend`, which makes the output `frontend/wailsjs/`. Change `api.ts`'s types with `types.ts` and the Go DTOs together.
- **The README and website screenshots come from `tools/screenshots/`** (macOS: `capture-all.sh --install` retakes every shot from the mock; see its README). Adding or changing a scenario that a screenshot shows means updating its shot list there; the mock is only bundled with `VITE_MOCK=1` or in dev.
- **The language and scanlator filters are selectors once a series loads**, built from the site's `FilterOptions` (`Controller.Filters`, shown as `State.languages`/`scanlators`, null when the site lists none). Picking one applies at once: the controller's `ConfigureLoad` (`SetOptionsAndLoad`, via `optionsWriter.patch(patch, url)`) sets the filter and starts the load in one step, so the window never shows it as not applied (`Stale` is for typed values, until a reload). A value the series lacks falls back to `all`, the site's `Current` value, or no filter (`dropUnmatchedFilters`), and that fallback is saved too. A site that lists no languages can't be checked against them, so a language that matched nothing (a `NoChaptersError`) is dropped for that load only: the reload gets a copy of the settings with it cleared, the saved language stays (and is still saved), and the field shows cleared and disabled. The drop only happens when no scanlator filter could have caused the empty list (none typed, or one the site lists); a network failure keeps it.
- **The browser's window follows the site.** `State.browserVisibleAuto` (`browser.NeedsVisible` for the loaded URL: declared by the grabber, or escalated earlier this session) shows *Show the browser window* on and locked with a hint (`browserVisible.ts`), without touching the saved option. `State.browserAlert` is the browser's `Attention` message while its window may need the user; `BrowserAlert.tsx` shows it over the window, with `ShowBrowser` and `DismissBrowserAlert`, until the page renders or the load ends.
- **Options live in `gui.json`** in `os.UserConfigDir()/manga-downloader/` (0600, written atomically), next to the Manga Plus secret. Missing keys keep their defaults; a file that doesn't parse is a warning, not a failure.
- **Pack as is one choice of three** (chapters, volumes, one file), saved as `packAs` and mapped onto the CLI's `Bundle` and `Volumes` (`store.go`); a `gui.json` with only the old `bundle` key migrates. The Volumes box isn't an option: it's per load, starts from the site's volumes, and is what a volume run packs (see "Volumes" in `AGENTS.md`).
- **Convert images is two checkboxes** in the window, mapped to the one setting (`avif`, `avif,webp`, `webp`, `none`, see `convertImages.ts`). The setting itself is still the CLI's string, so any of the four loads. With EPUB the AVIF box shows ticked and disabled (`avifSwitchOf`) without touching the saved value, and the Reading direction control appears only for EPUB.
- **The update check runs on release builds only** (`Tag` set, `gui/update.go`, toolkit-free): once at startup, in the background, it asks GitHub's `releases/latest` and reports a newer release through `State.update`. A failed check goes to stderr only, never the window's log, and is cancelled at shutdown. Dev builds make no request. The status bar's "!" is always yellow (`--warning-solid`), whatever the bump, and links to the latest release.
- **The window opens in the system's theme**: `theme_*.go` per OS picks the window's first background colour from the system theme, with a lookup bounded to 500ms on Linux and macOS (`gsettings`, `defaults`; the registry on Windows). `theme_test.go` ties both colours to `--bg` in `frontend/src/styles.css`, so a designer changing `--bg` must update `theme.go` too. `golang.org/x/sys` is a direct dependency for the Windows registry lookup.
- **The CLI launches it**: `manga-downloader ui` starts `manga-downloader-gui` from next to the CLI (or `Manga Downloader.app` next to it on macOS, or PATH), detached. Wails names the bundle after `wails.json`'s `name`, which is what `cmd/launcher.go` checks. On Windows, a bare run that Explorer started (the only process on its console, `cmd/console_windows.go`) does the same; without the GUI it shows help and waits for Enter so the window doesn't vanish.
- **Brand sources are in `assets/brand/`** (`brand.md` has the palette and the mapping to the GUI tokens). The GUI's mascot and the README header read the SVGs directly, and the app icons live in `gui/build/` (the `appicon.png`, `windows/icon.ico` and `linux/icon.png` the release packages), with `assets/brand/app/appicon.svg` as their source. Soft is the default face; Happy is only for a run that saved everything and the empty state, never a failure. Below 48px use the `-small` artwork, where Happy is the same as Soft.
