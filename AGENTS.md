# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## Project

Go CLI (cobra) that downloads manga chapters from supported websites and packs them into CBZ files, plus a Wails desktop app in `gui/` (see "The GUI" below). Module: `github.com/elboletaire/manga-downloader`, Go 1.19.

## Commands

```bash
make install          # go mod download
make build            # clean + test + build unix binary (injects version via ldflags)
make build/all        # unix + windows binaries
make test             # go test -v ./... (uses richgo if installed)
go test ./ranges -run TestParse   # run a single test
make clean            # remove built binaries and *.cbz files
```

Unit test coverage is thin; real verification is the makefile smoke targets, which download from live sites — run them selectively. `make grabber` runs everything, `make grabber/html` all `PlainHTML` sites, `make grabber/<site>` just one.

Releases: the version lives only in the git tag (the makefile injects the short sha, the release workflow also injects `git describe`). There's no CHANGELOG and no hardcoded version. **`release.yaml` triggers on a *published GitHub Release*, not on a tag push** — pushing a tag alone releases nothing.

- **Website**: `website/` is the GitHub Pages site (Vite + TS, pnpm, deployed by `pages.yaml`). Its supported-sites list is parsed from this README's "Supported sites" section at build time, so keep that list's `- [domain (note)](url) \*` format and the "Show all N" count in sync. See `website/README.md`.
- **Homebrew**: `packaging/homebrew/tap/` holds the formula (CLI) and cask (desktop app) for `elboletaire/homebrew-tap`. Each published release runs a `homebrew` job in `release.yaml` and `release-gui.yaml`, which copies them into the tap and sets the version and sha256s with `scripts/update-homebrew.sh`. Both jobs share one concurrency group. Keep the asset names in those files in step with the release workflows. See `packaging/homebrew/README.md`.

## Architecture

The download flow lives in `core` (`core/download.go`, `Series.Download`), UI-agnostic so the CLI and the GUI share it. `cmd/root.go` (`Run`) is the CLI shell around it: it parses flags and renders the `core.Events` through `cmd/progress.go`. The steps:

1. `grabber.NewSite(url, settings)` → `IdentifySite()` calls `Test()` on each registered grabber (`grabber/site.go`), matching by domain or by fetching the URL. **Order matters**: domain-matching grabbers first, then `PlainHTML`, then the remaining fetch-testing ones.
2. The matched `Site` fetches title and chapters; the range argument (`ranges.Parse`, `1-10,12,15-20`) filters them.
3. Each fetched chapter is passed through `Chapter.SkipPages` (`--skip-pages`, see below) before anything is downloaded, inside `core.Download`.
4. Chapters download concurrently (`downloader.FetchChapter`), bounded by `--concurrency` (max 5) and `--concurrency-pages` (max 10). Pages are plain GETs with a Referer.
5. `packer` writes CBZ files (`PackSingle`, or `PackBundle` with `--bundle`), named via a text/template (`--filename-template`, `packer/filename.go`); duplicate names get a `v{{.Version}}` suffix. Both paths go through `namePages` (`packer/pack.go`), which sniffs each page's format to name it `000.jpg`, `001.png`, … and transcodes per `--convert-images`.

### The GUI (`gui/`)

The desktop app is a [Wails v2](https://wails.io) app in its own Go module (`gui/`, `go.mod` requiring `github.com/wailsapp/wails/v2`), so the CLI's `go.mod` never pulls the webview and `go install …@latest` stays light. Wails shows a React + TypeScript frontend (`gui/frontend/`, pnpm, vite, vitest) in the system's webview: WebKitGTK on Linux, WebView2 on Windows, WKWebView on macOS. Why Wails over Fyne: native file dialogs, a webview UI, and Windows builds that need no cgo, so they cross-compile from any host. Linux still needs cgo and the WebKitGTK headers.

- **Built by `release-gui.yaml`** (`wails build`, on native Linux runners for amd64 and arm64, a Linux runner for both Windows archs, and macOS for the universal bundle). Windows arm64 gets a native arm64 build, cross-compiled on Linux. Locally, `make build/gui` builds for the host (it needs the webview headers on Linux), and `make build/gui/windows` cross-compiles the exe with `CGO_ENABLED=0`. `make test/gui` runs the Go tests and vitest; `make build`/`make test` leave the GUI out, as `./...` stops at the nested module.
- **Build tags**: `desktop,production` (without `production` Wails refuses to start: it selects the real app instead of a stub), `nodynamic` (the AVIF decoder, see below), and `webkit2_41` on Linux (current distros only ship WebKitGTK 4.1). The release build is `wails build`; the makefile uses plain `go build`, so only the release gets the icon and manifest embedded into the Windows exe.
- **The seam is `core` + `notice`**, as for the CLI. `controller.go` is toolkit-free: the state, the selection, the run and the log. `app.go` is the bound `App`, a thin adapter that turns the controller into DTOs, pushes them to the window, and does the OS-specific bits (the folder picker, opening the folder). Keep logic in the controller so it's testable without a window.
- **Pushes are throttled**: `App.notify` (`app.go`, the controller's change signal, called from any goroutine) signals a one-slot channel, and one goroutine emits `state` at most every 100ms, always sending the last change. `selection` and `log` are sent only when their generation counter moved, since they can be thousands of entries. `chapters` is sent once per load. The window also calls `State()`, `Chapters()`, `Selection()` and `Log()` on mount, because events emitted before the listener registers are lost. Nothing is emitted before `OnStartup` or after `OnShutdown`.
- **The frontend talks to the backend only through `gui/frontend/src/api.ts`**, which wraps the generated `wailsjs/` bindings. `mock.ts` implements the same `Api` in memory: `pnpm dev` (or `?mock&scenario=…`, with the scenarios listed in the header of `mock.ts`) runs the UI in a plain browser without the Go app. The design pass works against it. The bindings are committed (`-skipbindings` in the release) and regenerated with `wails generate module` in an environment with the webview headers; keep `wails.json`'s `wailsjsdir` at `./frontend`, which makes the output `frontend/wailsjs/`. Change `api.ts`'s types with `types.ts` and the Go DTOs together.
- **The language and scanlator filters are selectors once a series loads**, built from the site's `FilterOptions` (`Controller.Filters`, shown as `State.languages`/`scanlators`, null when the site lists none). Picking one reloads at once. A value the series lacks falls back to `all`, the site's `Current` value, or no filter (`dropUnmatchedFilters`), and that fallback is saved too.
- **Options live in `gui.json`** in `os.UserConfigDir()/manga-downloader/` (0600, written atomically), next to the Manga Plus secret. Missing keys keep their defaults; a file that doesn't parse is a warning, not a failure.
- **Convert images is two checkboxes** in the window, mapped to the one setting (`avif`, `avif,webp`, `webp`, `none`, see `convertImages.ts`). The setting itself is still the CLI's string, so any of the four loads.
- **The update check runs on release builds only** (`Tag` set, `gui/update.go`, toolkit-free): once at startup, in the background, it asks GitHub's `releases/latest` and reports a newer release through `State.update`. A failed check goes to stderr only, never the window's log, and is cancelled at shutdown. Dev builds make no request. The status bar's "!" is always yellow (`--warning-solid`), whatever the bump, and links to the latest release.
- **The window opens in the system's theme**: `theme_*.go` per OS picks the window's first background colour from the system theme, with a lookup bounded to 500ms on Linux and macOS (`gsettings`, `defaults`; the registry on Windows). `theme_test.go` ties both colours to `--bg` in `frontend/src/styles.css`, so a designer changing `--bg` must update `theme.go` too. `golang.org/x/sys` is a direct dependency for the Windows registry lookup.
- **The CLI launches it**: `manga-downloader ui` starts `manga-downloader-gui` from next to the CLI (or `Manga Downloader.app` next to it on macOS, or PATH), detached. Wails names the bundle after `wails.json`'s `name`, which is what `cmd/launcher.go` checks. On Windows, a bare run that Explorer started (the only process on its console, `cmd/console_windows.go`) does the same; without the GUI it shows help and waits for Enter so the window doesn't vanish.
- **Brand sources are in `assets/brand/`** (`brand.md` has the palette and the mapping to the GUI tokens). The GUI's mascot and the README header read the SVGs directly, and the app icons live in `gui/build/` (the `appicon.png`, `windows/icon.ico` and `linux/icon.png` the release packages), with `assets/brand/app/appicon.svg` as their source. Soft is the default face; Happy is only for a run that saved everything and the empty state, never a failure. Below 48px use the `-small` artwork, where Happy is the same as Soft.

### Page conversion (`--convert-images`, #155)

Some sites serve pages e-readers can't render — AVIF (atsu.moe, mistscans, mangalib) and WebP (unreliable on e-ink). `packer/convert.go` re-encodes to JPEG q90: AVIF by default, WebP opt-in (`avif,webp`), `none` disables both.

- **The decoder is `github.com/gen2brain/avif` with `-tags nodynamic`** — libavif/dav1d as WASM under wazero, so `CGO_ENABLED=0` and the 8-way cross-compile matrix keep working (any cgo decoder is disqualified by that). The tag forces the embedded WASM instead of `dlopen`ing a system libavif. **It must stay in sync everywhere it's passed: `GOTAGS` and `GUI_TAGS` in the `makefile`, `build_flags` in `.github/workflows/release.yaml`, and the `-tags` lines in `.github/workflows/release-gui.yaml`** — the release is the only build path that bypasses the makefile, and the library silently degrades to WASM without the tag, so a mismatch is easy to miss.
- **The seam is `namePages`, not `grabber.Page.Transform`**: a `Transform` error re-runs the download retry loop, so a decode failure would pointlessly refetch the page. `namePages` is also where extensions are assigned, so converting there makes the `.jpg` follow automatically.
- **`flattenAlpha` composites onto white first**, because `jpeg.Encode` drops alpha rather than compositing — transparent margins would otherwise come out as solid black bars. Already-opaque images pass through untouched to keep `jpeg.Encode`'s fast path.
- **A page that fails to convert keeps its original bytes *and* extension**, with a warning: `pack()` has no partial-success path, so erroring would lose the whole chapter (or bundle) over one page. The extension must never claim `.jpg` for non-JPEG bytes.
- **`tools/verify-cbz` is what actually proves conversion happened in CI**, precisely because that failure is non-fatal: it rejects `.avif` entries (`-allow-avif` for `--convert-images=none` archives) and checks entry names against sniffed content.
- The WebP test fixture is a real file inlined as bytes (`x/image/webp` is decode-only, and Go has no test-only dependency scope), which also pins the load-bearing blank import in `convert.go`.

### Page skipping (`--skip-pages`)

Scanlation groups reserve pages for credits/ads (tcbscans: always page 2, often the last one too), and a page that 404s on the site's end fails the *whole* chapter with no way around it — `https://tcbonepiecechapters.com/chapters/7855/one-piece-chapter-1146` was flatly undownloadable until this flag existed. `Chapter.SkipPages` (`grabber/chapter.go`) drops the selected pages, called from `core.Download` right after `FetchChapter`.

- **Positions are 1-based indices into `chapter.Pages`, never `Page.Number`.** That field is not a position: most grabbers set `i+1`, a couple (`mgeko`, `projectsuki`) set a bare `i`, and `tcb` sets the *reader page* number, which several images share. `SkipPages` deliberately leaves `Page.Number` alone afterwards, so a download error still names the page the site numbers; the archive stays contiguous anyway because `namePages` numbers by slice index.
- **Skipping happens before the download, not at packing time.** That's the entire point (a skipped page costs nothing and can't 404 the chapter), and `downloader.FetchChapter` aborts the chapter on the first page error, so a post-download filter could never rescue a broken page.
- **`core.Download` calls `FetchChapter` twice in `--bundle` mode** — once in the totals loop that sizes the progress bar, once in the download goroutine. Any per-chapter filtering has to be applied at *both*, or the bar never reaches its total and `p.Wait()` hangs until the `Abort` fallback. `SkipPages` also updates `PagesCount` for the same reason.
- **`ranges.Parse` rejects negatives; `ranges.ParseRelative` accepts them.** Two entry points rather than one, because counting from the end is meaningless for chapter *numbers* (and chapter 0 exists), so the chapter-range caller should fail loudly on a negative instead of filtering nothing. `ranges.Resolve(rngs, total)` is what turns `-1` into a position, per chapter.
- The parser is regex-based now: it used to `strings.Split(part, "-")`, which can't tell `-3--1` apart from anything. Reversed ranges still clamp to their first bound (`10-5` → just 10) as they always have, but only when both bounds share a sign — `2--1` ("page 2 to the last") is ordered, just not comparably so until `Resolve` knows the total.
- **pflag takes the argument after a long flag verbatim, dash and all**, so `--skip-pages -1` works and the `=` form isn't actually required (`parseLongArg` never inspects the value for a leading `-`). A *shorthand* would be a different story, which is why this flag has none. The README documents both forms.

### The grabber package

- `Site` (`grabber/site.go`) is the contract: `Test`, `FetchTitle`, `FetchChapters`, `FetchChapter`, … The base `Grabber` provides shared settings/helpers.
- `Filterable`/`Filterables` (`filterable.go`) abstracts chapters for sorting/filtering by number; each grabber has its own chapter struct embedding `grabber.Chapter`.
- **`PlainHTML`** (`plainhtml.go`): generic goquery scraper driven by a list of `SiteSelector` entries. Order in that list matters — a loose entry shadows later ones. `getPlainHTMLImageURL` handles readers that don't just expose `<img src>` (see patterns below).
- **`PlainHTMLBrowser`** (`plainhtmlbrowser.go`): same selector parsing, but matches **by domain** (`browserSelectors`, no fetch — starting a browser is expensive) and renders through Chrome. Registered first in `IdentifySite()`.
- **The two selector lists are the source of truth for which sites are covered** — they drift constantly, so read them rather than any list in this file.
- Dedicated grabbers exist where selectors can't work: `inmanga`, `mangadex` (API-based, language-aware), `manganelo` (mangabats + mangakakalot + natomanga + manganato.gg: the DOM renders only the newest 50 chapters, the full list comes from a paginated JSON API), `mangafire` (browser-driven, see below), `mangak`, `qimanga`, `tcb` (Madara), `leercapitulo`, `witchtoons`, `teamshadowi`, `baozimh`, `atsumaru`, `mkissa`, `fanfox`, `mangatown` (the mangahere family without chapterfun.ashx: one HTML document per reader page, count from `total_pages`; m. host and chapter URLs are rewritten to the www series URL), `webtoons` (episode list from the m.webtoons.com `/api/v1/{webtoon|canvas}/{titleNo}/episodes` cursor API with pageSize=1000, HTML list walk as fallback; canvas ids only answer on the canvas route; the image CDN 403s without a webtoons.com Referer; free episodes only, since locked ones aren't listed on the web), and others.
- **`baozimh.go`** (包子漫画) is plain HTML but **geo-routed by visitor IP**: mainland-China IPs get simplified-script pages, everyone else traditional. Same markup either way, but the chapter-number regex must accept both `话`/`話` (a hardcoded one silently drops every chapter for half the world) and a bare leading number, while rejecting digit-led dates in code since RE2 has no lookahead. Long chapters span several reader pages linked by a "next page" link with overlapping images, merged and deduped by CDN URL. Repeated chapter *numbers* are often genuinely distinct files and all download. baozimh.com itself now 403s us, so the smoke target and README use the www.twmanga.com mirror (same grabber; `Test()` accepts both). Reader URLs (`/comic/chapter/<slug>/...`) are mapped to the series by `baozimhSeriesURL`.
- **`mangaplus.go`** (Manga Plus) talks to the **app API** (`jumpg-api.tokyo-cdn.com`), not the website's: that one serves a truncated chapter list and paywalls the middle of a running series. Responses are **protobuf**, read by `protobuf.go` (a minimal wire-format reader, no runtime or generated code). Every call needs the base params (`os`, `os_ver`, `app_ver`) and an **anonymous device `secret`**, registered with `PUT /register` and cached (0600) under the user config dir; `MANGAPLUS_SECRET` overrides it, and a cached one the API rejects is re-registered once. The complete list is `chapter_list_v2` (field 38) of `title_detailV3`; `chapter_list_group` (28) is only a fallback. Chapters are **not filtered by `chapter_type`** — one read for free flips to `STANDARD` and stays readable — only the API's refusal (11301/11302) is an error. `manga_viewer_v3` mints a `plus_vw_token` **per response**, bound to that response's signed image URLs and only present in its `Set-Cookie`, so the app API uses its own `net/http` client and the token travels as `Page.Headers` (`Plus-Vw-Token` plus an explicit `Cookie`), never the shared session; viewer responses are cached per chapter because `--bundle` fetches every chapter twice. The API **rate limits hard** (~10 calls in a few seconds is error 10522 and a 10+ minute lockout), so calls are spaced 500ms apart and the first 10522 makes every later call fail locally. Names aren't always numbers (`#001-1`, `ex`), so numbers are derived in order and kept strictly increasing: split parts go in the hundredths (`#001-1` is 1.01), unnumbered chapters get `previous + 0.1`. A `title_id` is **one edition per language**, each with its own chapter list (some list the whole run, others only the six-chapter free window), and `lang`/`clang` can't switch between them: `--language` looks the edition's id up in `title_languages` (field 27) and refetches its detail. `Chapter.Language` keeps the API's three-letter code (`eng`, `esp`), which is what `clang` sends.

### The browser package

`browser/browser.go` drives a locally-installed Chromium (auto-discovered by chromedp) for sites plain HTTP can't scrape. One process, started lazily and reused. `GetHTML` returns rendered HTML and harvests cookies + UA into `http/session.go`, so images still download over fast plain HTTP reusing the browser's Cloudflare clearance. Variants: `GetHTMLWithScroll`, `GetReaderHTML`, `GetAPIResponses`.

- **Always try the site's own API/HTTP first.** mangafire's API was wide open until it started signing calls with a CF-gated `vrf` token (403 "Missing token"), forcing a browser; zonatmo went the other way and dropped its TLS block. Re-verify instead of assuming either direction is permanent.
- **Headless loses to Cloudflare; headed usually wins.** `GetHTML` handles this: a short headless probe, then a teardown and reopen as visible on `challengeError`. `--browser-visible` skips the wasted probe.
- **Interactive "Verify you are human" checkboxes are auto-clicked.** Whenever the browser is headed, `startChallengeClicker` polls in the background and CDP-clicks the Turnstile checkbox (the widget's an unqueryable closed shadow root, so it targets the full-width ~68px host row in `div.main-content`; CDP mouse events are `isTrusted:true`, which Turnstile accepts). This is what lets the docker `:browser` image — whose "visible" window is an unattended Xvfb framebuffer — pass interactive challenges, not just managed ones.
- **Running in a container needs `--no-sandbox` + a writable HOME.** `start()` adds `chromedp.NoSandbox` when `inContainer()` (detects `/.dockerenv`, `/run/.containerenv`, or `BROWSER_NO_SANDBOX=1`) — chrome's setuid/userns sandbox can't init in an unprivileged container. Alpine chromium also dies with a misleading `chrome_crashpad_handler: --database is required` when `$HOME` isn't writable; `entrypoint.sh` (shared by both images) creates `/home/manga` for the runtime user, which the Manga Plus secret cache needs too. See `docker/Dockerfile.browser` (chromium + xvfb + CJK fonts) and `docker/entrypoint-browser.sh` (Xvfb `:99` wrapper).
- **A theme tells you nothing about the hosting.** The same themesia or Madara markup is plain HTTP on one domain and CF-gated on another — check, don't assume.
- **`tools/probe`** renders a URL and tests selectors. Env knobs: `PROBE_VISIBLE=1`, `PROBE_TIMEOUT=4m` (default 45s), `PROBE_SLEEP=8s` (settle for lazy SPAs), `PROBE_DUMP=/tmp/x.html`, `PROBE_NETLOG=1` (log non-asset responses — how mangafire's API was found), `PROBE_FETCH_SEL` (test a plain-HTTP image download with the harvested session), `PROBE_API_URL` + `PROBE_API_DUMP_DIR` (fetch JSON APIs reusing the session; checks cookie carry-over to e.g. an `api.` subdomain).

### Reader patterns worth reusing

Most "the images aren't in the HTML" walls are plain data in disguise. Already implemented, and each generalizes to other sites:

- **`ts_reader.run(...)` blob** — every mangastream/themesia site, handled generically.
- **FoOlSlide `var pages = [...]`** — only the current page renders, but all URLs sit in that array (deathtollscans, furyosociety).
- **`${uid}` template literal** — `<img>` has a placeholder `src` plus a `uid`; the CDN prefix is regexed out of the page's own script rather than hardcoded, so it survives a CDN change (writerscans, mistscans, asmotoon).
- **Named JS array with an unstable variable name** — find the name from the assignment call, then pull the literal by name (mangakatana).
- **Alpine `x-data="immersiveReader({pages, baseLink})"`** — goquery decodes the escaped JSON via `.Attr()` (ritharscans). The live form is now `pages: JSON.parse('[...]')` with absolute CDN paths and a JS-escaped `baseLink`, decoded by `unescapeJSString` (`plainhtml.go`); the older literal relative-path form is still handled.
- **P.A.C.K.E.R.-packed JS** — a documented base-N token substitution, not a cipher; unpacks in pure Go with no JS engine (`unpackPackerJS` in `fanfox.go`). Don't reach for a browser just because a response starts with `eval(function(p,a,c,k,e,d)`.
- **TanStack Start / seroval page data** (hivetoons, vortexscans, azorafly) — the series page renders only the newest ~20 chapters, but the full list sits in an `initialChapters:$R[n]=[...]` literal followed by `,totalChapterCount:N`. `tanstackcomic.go` extracts it with `extractBalancedJSON` and `serovalToJSON` (unquoted keys, `!0`/`!1`, `void 0`, `$R[n]=` definitions); guard the list against the total so a shape change fails loudly.
- **Next.js RSC payloads** — `self.__next_f.push` chunks must be concatenated before searching (`nextFlightStream`), then `extractBalancedJSON` pulls a value by key marker, brace/bracket-matching through quoted strings, for objects and arrays alike. Sibling keys often can't share one struct, since the wrapper is a react element tuple — extract each separately (teamshadowi, witchtoons, templetoons).
- **Virtualized/infinite-scroll readers** — `GetHTMLWithScroll` steps through the *growing* `scrollHeight`, so the page count needn't be known up front (comix.to).
- **A CF 403 on one route may only be a direct-navigation rule** — mkissa's reader 403s on any direct navigation (cookie warm-up doesn't help) but loads fine when reached by clicking through the app's own routing, which issues no navigation request. `GetReaderHTML` generalizes this plus plateau-scrolling.

### Rules learned the hard way

- **Paywalls mostly look like success.** Recent chapters commonly render zero images with no error, or replace the link with a modal. Several `Rows` selectors end in `a[href]` just to filter those out. **Smoke-test a chapter slightly behind the latest**, never the newest.
- **Verify CBZ contents, not their existence.** A run can "succeed" with empty or junk archives; `tools/verify-cbz` checks sizes and magic bytes.
- **Chapter titles need `sanitizeTitle()` too**, not just series titles — several themes pad `.chapternum` with raw tabs/newlines or mix in a trailing date, which leaked into filenames.
- **Scope bare `h1` selectors** — sidebar labels and decorative stat headings are common (`h1[itemprop="name"]`).
- **Scope Madara reader selectors** — `div.reading-content img` picks up decorative banners/footers on some sites, and `body.Find("li")` matches "Volume N" wrappers as bogus chapters.
- **`tcb.go`'s `Test()` is domain-agnostic**, so any Madara site with the same `ajax/chapters` endpoint works with zero code — just a smoke target and a README line (mangasushi, mangalivre.to were both free this way).
- **A chapter list stopping at a round number is probably pruning, not a cap — and HTTP 200 on older chapter URLs proves nothing.** The audit after #169 read manhuaplus.com as capping at the newest 500 rows: one series listed exactly 500 (ch 280–529.1) in both the series HTML and `ajax/chapters/`, yet `chapter-1/` answered 200. Both signals were wrong — the 200 is a soft-404 serving the *series page* (canonical points at the series, no reader content), and a sibling series lists 3364 rows, so there is no newest-N cap; the site just deletes old chapters and 500 was a coincidence. Cross-check row counts against the Yoast `wp-manga-chapters-sitemap*.xml` on Madara sites (it matched both series exactly), and don't hunt for a recovery route: `wp/v2` exposes no chapter routes, `ajax/chapters/` ignores `t`/`per_page`/`offset`/`chapter_page`, and `manga_get_chapters` 400s. `cmd/root.go` warns when a *user-supplied* range dips below the first listed chapter — deliberately silent on the implicit all-chapters range, which would otherwise fire on every continuation series and every `--language`-thinned list. Surviving old chapters can still be rotten: manhuaplus pages from the 2020 `*.files.wordpress.com` era return HTML instead of an image (200), which only `tools/verify-cbz` catches; `cdn.manhuaplus.com` ones (~2021 on) are fine.
- **A wait selector matching the first element isn't proof the rest loaded** — readers that append images progressively need `BrowserSiteSelector.Settle`. Verify by re-counting matches at increasing `PROBE_SLEEP` until the count stops growing.
- **A CF challenge timing out on a rich selector may just be too specific too early** — wait on `"body"`, dump, then find the real selectors.
- The makefile is tracked lowercase; on macOS `git add` needs the lowercase name. macOS also has no `timeout`.
- **Use a temp dir namespaced to your agent/worktree** when investigating — generic `/tmp/series.html` paths collide across parallel agents and get overwritten mid-investigation.

### Investigating a new site

Triage with curl first: fetch with a browser UA and check the `<title>`. "Just a moment…" means a CF JS challenge; TLS drops, empty SPA shells and encrypted-image readers are equally out for plain HTTP. But check the *content*, not just status/size — fanfox returns complete HTML yet swaps every series page for an age gate until an `isAdult=1` cookie is sent, and a 200 can be a parked or ransom page. 403/500 in the app but 200 in curl almost always means headers (`http/request.go` sends UA, Accept, Accept-Language and a trailing-slash referer, all because some site demanded them). Old chapters are often dropped from CDNs, so "chapter 1" is usually the worst test target. And a near-empty `grep '<img src="'` proves nothing — attributes may be single-quoted, and `grep -c` on minified HTML counts lines, not matches.

Then:

- Plain HTML → add a `SiteSelector` to `PlainHTML.Test()`, plus a `grabber/html` smoke target and a README line.
- Needs a browser but selector-friendly → add a `BrowserSiteSelector` to `browserSelectors`.
- Otherwise → new grabber implementing `Site` (embed `*Grabber`), registered in `IdentifySite()`, with its own smoke target in the top-level `grabber:` aggregate (not `grabber/html`).

### Sites that moved, or that we deliberately don't support

Sites rebrand constantly; probe for a successor before declaring one dead, and don't guess slug patterns — get a real series URL from the site's own listing.

- **Moved, still supported**: tcbscans → tcbonepiecechapters; mangabat → mangabats; asuratoon → asurascans; zonatmo.com → zonatmo.org (seized Apr 2026); aurorascans → qimanhwa → qimanga; mangalivre.tv/.net → mangalivre.to; mangabuddy → mangak.io; witchscans → witchtoons.net; mangapark.to/.io/.page → mangapark1.com; utoon.net (now a "site suspended" hijack page) → utoon.us; kaynscan.org → kaynscans.com (Aug 2026: the Astro/astro-island platform is gone, the new domain runs the same Next.js RSC platform as witchtoons.net — shared in `rsccomic.go` — and the old domain 301s over remapping `/series/{slug}` to `/series/comic/{slug}`, a rewrite the grabber also applies in code); elftoon.com → elftoon.net (same RSC platform, `/manga/{slug}` remapped to `/series/comic/{slug}` in code); mangaball.net → mangaball.com; baozimh.com → twmanga.com (mirror; baozimh.com 403s).
- **mangapark1.com** (Aug 2026; mangapark.to/.io/.page redirect there or are dead, and their `/series/{slug}` URLs keep the same slug, so `mangaparkSeriesURL` maps any accepted URL, reader ones included, to `https://mangapark1.com/manga/{slug}`). The site is a different platform: series at `/manga/{slug}`, readers at `/read/{slug}/chapter-N`; the old `/series/` and `get-chapter-list` paths are gone. The Cloudflare challenge is passed by the browser, but the harvested clearance doesn't carry to HTML over Go's HTTP client (403 on every page), only to the image CDN. So **every HTML page is rendered through the browser, `FetchChapter` included** (this reverses the earlier "don't reach for the browser in FetchChapter" advice). `fetchMangaparkPage` tries plain HTTP first, but once one plain request gets a 403 (`mangaparkPlainBlocked`, set from the typed `http.StatusError`) the rest of the run goes straight to the browser. The ~200 page images per chapter still download over plain HTTP. The series page lists only its newest 20 chapters, so the full list comes from the `select.chapter-dropdown` of a reader page. The wait selectors are `a[href*="/read/"]` (series; the 404 page has none) and `img.image-thumb[data-number]` (reader), never `body`, which the interstitial would pass.
- **witchtoons.net** deserves a note: the redirect from witchscans drops the path and the platform changed entirely, so old URLs can't be remapped. It's server-rendered Next.js, so no browser — but the chapter list is in the RSC payload, not the DOM (the series page renders exactly *one* chapter link, so a selector-driven grabber sees 1 of 61 and looks like it works), and is paginated at 100 per page. Page URLs are signed with a ~1h TTL, harmless since they download immediately.
- **colamanga** (#30): app-gated reader on top of client-side image encryption. Not feasible.
- **comick.dev**: CF is beatable and the chapter-list JSON is reachable, but the page-image endpoint returns `[]` anonymously for every chapter tried, and the live reader receives no images either. Needs an account.
- **sakuramangas.org** (#90): the wall is client-side image decryption, **not** Cloudflare — two earlier investigations got this wrong. Pages exist only as `blob:`s their cipher decodes on genuine, dwelt human interaction; every automated recipe produced zero decoded images, and direct URLs 403 past the first few. Beating it properly means reverse-engineering rotating obfuscated keys, PoW headers and CSRF tokens — the stack that got the dedicated Tachiyomi extension delisted. Not worth it. Two techniques from it *are* reusable, though:
  - **CF clearance by attaching to a user-launched Chrome**: a Chrome the user starts with `--remote-debugging-port` (no debugger attached at challenge time) clears the challenge; chromedp then attaches via `NewRemoteAllocator` and reuses the cached `cf_clearance`, plus `BringToFront()` since attached tabs are backgrounded. It's our chromedp-*launched* Chrome that CF detects, not headed mode — so this is the move for "works in my Chrome, not in automated Chrome".
  - **CDP `Input.dispatch*Event` produces `isTrusted:true` events**, which drive reader gestures that a page's JS ignores from synthetic `dispatchEvent`/`.click()` calls.
