# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Go CLI (cobra) that downloads manga chapters from supported websites and packs them into CBZ files. Module: `github.com/elboletaire/manga-downloader`, Go 1.19.

## Commands

```bash
make install          # go mod download
make build            # clean + test + build unix binary (injects version via ldflags)
make build/all        # unix + windows binaries
make test             # go test -v ./... (uses richgo if installed)
go test ./ranges -run TestParse   # run a single test
make clean            # remove built binaries and *.cbz files
```

Unit test coverage is thin. Real-world verification is done with the makefile smoke targets, which run the app against live sites:

```bash
make grabber          # all of the below
make grabber/inmanga
make grabber/mangadex
make grabber/mangabats
make grabber/tcb
make grabber/html     # runs a list of plainhtml-based sites
```

These hit live websites and download actual chapters, so run them selectively.

## Architecture

The download flow, all orchestrated from `cmd/root.go` (`Run`):

1. `grabber.NewSite(url, settings)` → `IdentifySite()` iterates the registered grabbers (`grabber/site.go`) and calls `Test()` on each, which checks (by domain, or by fetching the URL) whether the site matches. **Order matters**: domain-matching grabbers go first, then `PlainHTML`, then the remaining fetch-testing ones.
2. The matched `Site` fetches title and chapters (`FetchChapters` returns `Filterables`), and the user's range argument (`ranges.Parse`, format `1-10,12,15-20`) filters them.
3. Chapters download concurrently (`downloader.FetchChapter`), bounded by `--concurrency` (chapters, max 5) and `--concurrency-pages` (max 10) semaphores. Pages are fetched via the `http` package (plain GETs with a Referer header).
4. `packer` writes CBZ files (`PackSingle` per chapter or `PackBundle` with `--bundle`), naming them via a Go text/template (`--filename-template`, parts in `packer/filename.go`). Duplicate filenames get a `v{{.Version}}` suffix instead of being overwritten. Both entry points go through `namePages` (`packer/pack.go`), which sniffs each page's format (`extFromContent`) to name it `000.jpg`, `001.png`, ... — and transcodes the formats listed in `--convert-images` to JPEG on the way.

### Page conversion (`--convert-images`, issue #155)

Some sites serve pages in formats dedicated e-readers can't render — **AVIF** (atsu.moe, mistscans.com, mangalib.me: Calibre/KCC, Kobo's CBZ reader and KOReader/MuPDF all fail) and **WebP** (unreliable on e-ink). `packer/convert.go` re-encodes them to JPEG at quality 90; AVIF converts by default, WebP is opt-in (`--convert-images avif,webp`), `none` disables both. `grabber/convert.go` parses the flag into a `ConvertFormats` string set keyed by the same names `extFromContent` returns, so the call site is just `formats.Has(ext)` with no translation table.

- **The decoder is `github.com/gen2brain/avif` built with `-tags nodynamic`** — upstream libavif/dav1d compiled to WASM and run under wazero, so `CGO_ENABLED=0` and the 7-way cross-compiled release matrix keep working (any cgo AVIF decoder is disqualified outright by that). The tag forces the embedded WASM instead of `dlopen`ing whatever system libavif a machine happens to have, so decoding is identical for devs, CI and released binaries. **It's set in two places that must stay in sync: `GOTAGS` in the `makefile` and `build_flags` in `.github/workflows/release.yaml`** (the only build path that bypasses the makefile — the easiest thing to forget and the most damaging to miss). Without the tag the library still degrades to WASM when no libavif is found, which is why the tag-less `go run .` smoke targets convert correctly on CI anyway.
- **The seam is `namePages`, deliberately not the `grabber.Page.Transform` hook**: a transform error inside `downloader.FetchFile` re-runs the whole retry loop *including re-downloading the page*, so a decode failure would pointlessly refetch. `namePages` is also the single place extensions are assigned, so converting before naming makes the `.jpg` follow automatically.
- **JPEG has no alpha and `jpeg.Encode` drops it rather than compositing**, so the `{0,0,0,0}` transparent pixels AVIF/WebP pages use would encode as *solid black* — a page with transparent margins would come out with black bars. `flattenAlpha` composites onto white first, but returns already-opaque images untouched so a lossy WebP's `*image.YCbCr` keeps `jpeg.Encode`'s no-conversion fast path.
- **A page that fails to convert keeps its original bytes *and* its original extension**, with a yellow warning. `pack()` has no partial-success path, so returning an error would lose the whole chapter — the whole bundle, in bundle mode — over one bad page. The extension must never say `.jpg` for non-JPEG bytes.
- **`tools/verify-cbz` is what actually proves conversion happened in CI**, precisely because that failure handling is non-fatal: an `.avif` entry fails (with `-allow-avif` to check `--convert-images=none` archives), and entry names are checked against their sniffed content. The `grabber/atsumaru` and `grabber/mistscans` smoke targets cover the real AVIF sites end to end.
- The WebP fixture can't be generated at runtime like the AVIF one: `golang.org/x/image/webp` is decode-only, and Go has no test-only dependency scope to add an encoder in. `tinyWebP` in `packer/convert_test.go` is a real WebP file inlined as bytes (from `x/image/webp`'s own testdata), run through the unstubbed pipeline — which also pins the load-bearing blank import of the decoder in `convert.go`.

### The grabber package

- `Site` interface (`grabber/site.go`) is the contract for all grabbers: `Test`, `FetchTitle`, `FetchChapters`, `FetchChapter`, etc. The base `Grabber` struct provides shared settings/helpers.
- `Filterable`/`Filterables` (`grabber/filterable.go`) abstracts chapters so they can be sorted/filtered by number; each grabber has its own chapter struct embedding `grabber.Chapter`.
- `PlainHTML` (`grabber/plainhtml.go`) is a generic goquery scraper driven by a list of `SiteSelector` entries (CSS selectors for title/rows/chapter/image). **The annotated list in `PlainHTML.Test()` is the source of truth for which sites it covers** — it drifts constantly, so read it rather than any list here. Selector order in that list matters, because some sites have very similar markup and a loose entry will shadow a later one.
- `getPlainHTMLImageURL` (same file) is where reader pages that don't just expose `<img src>` are handled; see "Reader patterns worth reusing" below for the branches it has.
- Site-specific grabbers with their own logic: `inmanga.go`, `mangadex.go` (both API-based, language-aware), `mangabats.go` (JSON chapters API + js image variables), `mangafire.go` (react SPA whose JSON API — `/api/titles/{hid}` + paginated `/chapters` + `/api/chapters/{id}` for pages — signs every call with a per-session, cloudflare-challenge-gated `vrf` token, so plain HTTP 403s "Missing token"; it drives a headless browser via `browser.GetAPIResponses` to let the page make the signed calls and intercepts the JSON responses, paginating by clicking the reader's own pager; images then download over plain HTTP), `mangak.go` (mangak.io, the mangabuddy rebrand: Next.js, chapter list and page images from the `__NEXT_DATA__` blob — the visible HTML lists only ~6 chapters, and the JSON `number` field is a 1-based ordinal so the real number is parsed from the chapter name), `qimanga.go` (paginated JSON chapters API + SSR reader), `tcb.go` (Madara wordpress sites, i.e. lhtranslation.net), `leercapitulo.go`, `witchtoons.go`, `teamshadowi.go`, `baozimh.go`.
- **`baozimh.go`** (baozimh.com / twmanga.com / cn.bzmgcn.com, 包子漫画) is plain server-rendered HTML end to end, **but geo-routed by visitor IP**: mainland-China IPs get simplified-script pages (baozimh.com 301s to cn.bzmgcn.com, reader on cn.cnbzmg.com), everyone else gets traditional-script pages (baozimh.com or www.twmanga.com). Both scripts share markup/selectors. Gotchas, all load-bearing:
  - The chapter number is parsed from the **start of the title text**: most series use `第N[话話]` (the class covers both scripts — a hardcoded 话 silently drops every chapter for traditional-script visitors), but some list a bare number first (`001 傳染`, `29 小餅乾（上）`, even `40支援 （下）` with no space), so the regex matches a leading `N` with or without the `第…話` wrapper, and rejects digit-led dates (`7月18號正式上線！` launch notices) in code, since RE2 has no lookahead. The title text is authoritative over `chapter_slot`, which is off by one (slot 108 = 第109话). Entries with no number (序章 prologue, 後記/后记 afterword, 番外 bonus, 更新調整 notices, cross-series promos) are skipped.
  - The chapter list lives in two containers (`#chapter-items`, a short preview strip, and `#chapters_other_list`, the full list), so `FetchChapters` scopes to both plus a URL dedup — rows are also re-listed outside those containers.
  - **Long chapters are split across several reader pages** (each part titled `第N話(k/M)`, up to ~50 images). Parts link each other with a 下一頁/下一页 link and overlap by a few pages, so `FetchChapter` follows that link until the last part (which has only 上一頁 and 下一話, the next *chapter*) and dedupes pages by CDN URL, plus a check that each part's `<title>` still carries the same chapter number before merging.
  - Reader pages embed pages as `<amp-img id="chapter-img-N-M" src=...>`, alongside an AMP-fallback `<img>` per page and a bottom "recommended comics" widget whose covers share the `amp-img` tag but carry no chapter-img id — hence the `amp-img[id^="chapter-img-"]` scoping. A chapter yielding zero pages errors out (premium/early-access locked) rather than producing an empty archive.
  - **Duplicate chapter *numbers* can be genuinely distinct files** (two 第112話 season finales; or per-part entries like `29 小餅乾（上）`/`（下）`), and all of them download: non-bundle mode yields a `v2` filename, `--bundle` keeps `Chapter 0112/` and `Chapter 0112 (2)/`. Both bars show a harmless `[zh]` tag, since `hasDuplicateChapterNumbers` can't tell those apart from per-language duplicates.

### The browser package

`browser/browser.go` drives a locally-installed Chromium browser (Chrome/Chromium/Brave/Edge, auto-discovered by chromedp's `ExecAllocator`) for sites plain HTTP can't scrape: JS-rendered pages, TLS-fingerprint blocks, or Cloudflare challenges. One shared browser process is started lazily and reused. `GetHTML(url, waitSelector, timeout)` returns rendered HTML and harvests the session cookies + real UA into the `http` package (`http/session.go`), so images still download via the fast plain-HTTP path reusing the browser's Cloudflare clearance. Variants: `GetHTMLWithScroll`, `GetHTMLWithLocalStorage`, `GetReaderHTML`, `GetAPIResponses` (see the patterns below for what each is for).

`grabber/plainhtmlbrowser.go` (`PlainHTMLBrowser`) is the browser-rendered twin of `PlainHTML`: it reuses all the selector-driven parsing (`chapterFromDoc`), but matches sites **by domain** (the `browserSelectors` list of `BrowserSiteSelector` — no fetch, since starting a browser is expensive) and fetches series/reader pages through Chrome. Registered first in `IdentifySite()`. `browserSelectors` is the source of truth for coverage (currently toongod.org, dragontea.ink, manhuaus.com, toonily.com, setsuscans.com, kappabeast.com, sushiscan.net, drakecomic.org, mangakakalot.gg, natomanga.com, mangahub.io, manhuatop.org).

- **Always try the site's own API/HTTP first; only reach for `PlainHTMLBrowser` when HTTP genuinely can't get the data.** mangafire's JSON API used to be wide open, but as of 2026-08 it signs every call with a per-session, CF-challenge-gated `vrf` token (plain HTTP → 403 "Missing token"), so `mangafire.go` is now browser-based — an open API can lock down later, so re-verify instead of assuming. The reverse happens too: zonatmo's successor domain dropped its TLS block and is plain `PlainHTML` now.
- **A cloudflare-fronted *theme* doesn't mean a cloudflare-fronted *site*.** silentquill.net, violetscans.org and rokaricomics.com all run the same mangastream/themesia markup as the browser-only sushiscan.net (`#chapterlist li` / `.chapternum` / `ts_reader.run`) but answer plain HTTP with no challenge — same theme, different hosting. Don't assume every themesia site needs a browser.
- **A Madara theme doesn't mean the plain-HTTP `Tcb` grabber will match, either.** setsuscans.com is stock Madara (`li.wp-manga-chapter`, `div.reading-content img`, even the same `manga/{slug}/ajax/chapters` endpoint `tcb.go` POSTs to) but sits behind a CF managed challenge that blocks that ajax endpoint too (curl POST → 403 "Just a moment..."), so `Tcb.Test()` never sees real HTML. It's a `PlainHTMLBrowser` domain entry instead: one visible-Chrome render clears the challenge, the AJAX-loaded list (`#manga-chapters-holder`, needs a few seconds' settle before `li.wp-manga-chapter` populates) comes through, and lazy `data-src` images download over plain HTTP afterwards.
- **Headless loses to Cloudflare; headed usually wins.** CDP automation is detectable, so CF challenges time out in headless mode. `browser.GetHTML` handles this automatically: it tries a short headless probe (`headlessProbeTimeout`) and, if the wait selector times out (a `challengeError`), tears down the headless browser and reopens a visible one (`goVisible`), where managed challenges resolve in a couple of seconds and the user can solve an interactive one manually. `--browser-visible` (`browser.SetVisible`) just forces headed from the start, skipping the wasted probe.
- **A CF challenge that keeps timing out on a rich selector may still pass in seconds — the selector is just too specific too early.** drakecomic.org repeatedly failed `GetHTML` waiting on `li.wp-manga-chapter`/`#chapterlist li` (up to 4 minutes, visible browser) even though `PROBE_NETLOG` showed the page answering 200 within seconds: its `<body>` genuinely renders empty at first and is populated a few seconds later by `admin-ajax.php`. `chromedp.WaitVisible` already polls until the selector appears, so waiting on `"body"` with a probe `PROBE_SLEEP`, then diffing the dump for the real selectors, unblocked it. Its images are CF-protected (403 to curl) but download fine via the harvested session.
- **A wait selector matching the first element isn't proof every element loaded.** mangahub.io's reader appends page `<img>` tags progressively (not virtualized-by-scroll, just staggered over seconds); `GetHTML`'s default zero settle returned as soon as the *first* `img.PB0mN` appeared, silently truncating a 16-page chapter to 6. `BrowserSiteSelector.Settle` (via `browser.SetSettle`) adds a fixed extra wait after the selector first matches. Verify these by re-counting selector matches with `PROBE_SLEEP` at increasing values until the count stops growing — a single probe run's count isn't trustworthy for pages that keep loading.
- **`tools/probe`** is the investigation tool: renders a URL in Chrome and tests selectors. Env knobs: `PROBE_VISIBLE=1` (headed), `PROBE_TIMEOUT=4m` (page-load timeout, default 45s — pair with a long `PROBE_SLEEP` to leave time for solving an interactive challenge manually), `PROBE_SLEEP=8s` (settle for lazy SPAs), `PROBE_DUMP=/tmp/x.html`, `PROBE_NETLOG=1` (log non-asset network responses — how mangafire's `/api/chapters/{id}` was found), `PROBE_FETCH_SEL="sel"` (grab the first matching image and test a plain-HTTP download with the harvested session), `PROBE_API_URL="url1,url2"` (after the browser clears a challenge, fetch arbitrary JSON APIs over plain HTTP reusing the session — checks whether cookies carry to another host, e.g. an `api.` subdomain; pair with `PROBE_API_DUMP_DIR=/tmp/x` for full bodies).

### Reader patterns worth reusing

Most "the images aren't in the HTML" walls turn out to be plain data in disguise. Branches already implemented in `getPlainHTMLImageURL` (or the browser package) that generalize to other sites:

- **`ts_reader.run(...)` blob** — mangastream/themesia theme, handled generically for every site on that theme.
- **FoOlSlide `var pages = [...]`** — the reader renders only the current page's `<img class="open">`, but every page's real URL is in that JSON array's `url` field (reader.deathtollscans.net, furyosociety.com).
- **`${uid}` template literal** — the `<img>` carries only a placeholder `src` plus an opaque `uid` attribute, and an inline script builds the real URL from a literal like `` `https://cdn.example.com/uploads/${uid}` ``. The prefix is regexed out of the page's own script (`uidTemplateRe`) rather than hardcoded, so it works for any site on this template even with a different CDN (writerscans.com, mistscans.com, asmotoon.com).
- **Named JS array with an unstable variable name** — mangakatana.com's `<img>`s only ever carry `data-src="#"`; the real URLs are in a plain array assigned client-side (`obj.attr('data-src', thzq[i])`) whose name changes between deployments. Find the name from the assignment call first, then pull the array literal by name. No rendering needed — it's just string data in the raw HTML.
- **Alpine.js `x-data` attribute** — ritharscans.com inlines every page's relative path plus a `baseLink` prefix in `x-data="immersiveReader({ pages: [...], baseLink: '...' })"`; goquery decodes the `&quot;`-escaped JSON transparently via `.Attr()`.
- **P.A.C.K.E.R.-packed JS** — fanfox resolves pages through `chapterfun.ashx?cid=...&page=N`, whose response uses the 20-year-old Dean Edwards packer (`eval(function(p,a,c,k,e,d){...})`). That's a deterministic, documented base-N token substitution, not a cipher; it unpacks in pure Go with no JS engine (`unpackPackerJS` in `fanfox.go`). Don't reach for a browser just because a response starts with `eval(function(p,a,c,k,e,d)`.
- **Next.js RSC ("flight") payloads are split across chunks, so they must be concatenated before searching.** `nextFlightStream()` (in `teamshadowi.go`) joins every `self.__next_f.push([1,"..."])` string back into one stream; `extractBalancedJSON()` then pulls a value out by key marker, brace/bracket-matching while respecting quoted strings, for **both objects and arrays**. Keys that look like they should share a wrapper often can't be unmarshalled as one struct, because the enclosing value is a react element tuple (`["$","$L6c",null,{...}]`) rather than a plain object — extract each key separately. Used by teamshadowi and witchtoons; templetoons parses a simpler flat `"pages":[...]` array the same way.
- **A client-side preference can be flipped instead of reversed.** leercapitulo.co hides pages in an obfuscated `#array_data` string, but its own JS decodes it fine — the real problem was that the reader showed one page at a time. Rendering it revealed a `localStorage` flag (`display_mode`) switching to "load all pages"; `browser.GetHTMLWithLocalStorage` (set key/value, reload, then wait/extract) generalizes this. Before declaring a reader "encrypted and unsupportable", check whether a browser alone already resolves the images.
- **A virtualized/infinite-scroll reader isn't a dead end.** comix.to mounts only a handful of `<img>`s near the top. `browser.GetHTMLWithScroll(url, waitSelector, iterations, pause, timeout)` scrolls in fractional steps of the page's *current* (growing) `scrollHeight`, letting an IntersectionObserver-driven reader mount everything — no need to know the page count up front; ~35 iterations at 600ms covers very different chapter lengths since each step re-reads the live scrollHeight.
- **A CF 403 on one route may only be a direct-navigation rule.** See mkissa below; `browser.GetReaderHTML` generalizes "click through the app's own routing, then plateau-scroll".

### Site-specific notes

- **`tcb.go`'s `Test()` is domain-agnostic** (regex `manga\/(.*)\/$` + a live POST to `{base}/manga/{slug}/ajax/chapters`), so any other Madara wordpress site with that ajax endpoint and `div.reading-content img[data-src]` markup is already supported with zero code changes — mangasushi.org and mangalivre.to were both found this way: no new grabber, no selector entry, just a makefile smoke target and a README line.
- **Madara's `div.reading-content img` isn't always clean.** manhuatop.org mixes a decorative `about_manhuatop_*.webp` banner and a `To_be_continued.webp` footer into the reader, sharing the `wp-manga-chapter-img` class with the real, sequentially-`id`'d page images — a plain selector smuggles them in as fake first/last pages, so its entry uses `div.reading-content img[id^="image-"]`. Similarly, **gdscans.com** groups chapters under "Volume N" `<li>` wrappers, so `tcb.go`'s original `body.Find("li")` matched those headers as bogus duplicate chapters (a spurious `v2` CBZ); scoping to `li.wp-manga-chapter` fixed it, and flat-list sites like lhtranslation.net were unaffected either way.
- **witchscans.com rebranded to witchtoons.net (August 2026)** and changed platform entirely, so it moved out of `PlainHTML` into its own `witchtoons.go`. The old domain 301s to the new one but **drops the path**, and series now live at `/series/comic/{slug}` with readers at `/series/comic/{slug}/chapter/{number}` (keyed by chapter *number*, not id), so old URLs can't be remapped and `Test()` only matches the new domain. Series slugs survived the migration. It's a Next.js App Router site but fully server-rendered, so plain HTTP suffices — the catch is that the data ships in the RSC payload, not the DOM: the series page renders exactly **one** chapter `<a>` (a "start reading" link), so a selector-driven grabber sees 1 of 61 chapters and looks like it works. The chapter list is paginated at **100 per page** via `?page=N` (`totalPages`/`currentPage` are siblings of `chapters`; a single-page series still ships `totalPages:1`), so a 290-chapter series silently yields its first 100 if you don't follow it. Page URLs are relative *and signed* (`?sig=...&exp=...`, ~1h TTL) so the query string must be kept verbatim — harmless, since pages download right after the reader fetch. Coin-locked chapters still list but ship zero pages, so `FetchChapter` errors rather than packing an empty archive.
- **atsu.moe** (Atsumaru) is a React SPA with a near-empty HTML shell, but its JSON API is wide open to plain HTTP with no cookies: `/api/manga/info?mangaId={id}` returns the title and the *full* chapter list in one uncapped call (no pagination, unlike mangafire/qimanga). Multiple scanlation groups (`scanId`) can upload the same chapter numbers and the API always mixes them with no per-group filter, so `atsumaru.go` picks the group with the most chapters and drops the rest to keep numbers unique. Readers are `/api/read/chapter?mangaId={id}&chapterId={chapterId}`; page images are plain AVIF under `/static/pages/...`, no referer/auth. Found purely by following `PROBE_NETLOG=1` — grepping the JS bundles for endpoint strings came up empty because they're built from a typed api-client object, not concatenation. Also: Go's `net/http.DetectContentType` doesn't know AVIF, so the shared `packer/imgfmt` sniff matches the ISOBMFF `ftyp` brand manually to avoid mislabeling pages `.jpg`.
- **mkissa.to** (`mkissa.go`) is a SvelteKit SPA over a GraphQL API using Apollo persisted queries (`api.mkissa.net/api?variables=...&extensions={"persistedQuery":{"sha256Hash":...}}`): the manga-info query — title plus the full per-chapter-number list, in `data.manga.availableChaptersDetail.sub` — answers plain HTTP with zero cookies. But the reader route 403s with a Turnstile challenge on *any* direct top-level navigation — even a chromedp session that first visited the series page and carried its cookies into a second `Navigate()` is blocked, ruling out a cookie warm-up. It loads fine when reached through the app's own client-side routing: render the series page, click the "Chapters" tab, then the chapter's `div[data-href=...]` (older chapters sit behind `.media-ep-list__pagination` buttons) — no real navigation request, so the WAF rule never fires. Its "encrypted" page list is moot: the decoded `<img class="reader-page__img">` elements are plain lazy-loaded JPEG/PNG URLs on a third-party CDN, downloadable with a plain UA+Referer. Getting every page requires scrolling, and some readers auto-continue into the *next* chapter past the last page (appending more `.reader-page` elements), so stop on a same-count plateau of images whose `src` contains `/{id}/{num}/` — not on a fixed total or a generic selector count.
- **demonicscans.org** is fully plain HTTP: server-rendered chapter list (`#chapters-list li`, `a.chplinks`) and a reader with full-size, non-lazy URLs (`img.imgholder`). Its CDN serves paths with literal unencoded spaces, which `net/http.NewRequest` percent-encodes automatically, so no special handling was needed.
- **sanascans.com**: the plain `sanascan.com` (no "s") domain is unrelated parked spam. It's server-rendered Astro (same island-hydration family as asurascans.com), so plain HTTP gets everything. Its series page has decorative `<h1>` stat labels besides the real title, so scope to `h1[itemprop="name"]`; rows are `a[data-astro-prefetch][href*="/chapter-"]` (hyphenated, unlike asurascans' slashed `/chapter/14`, so the two don't collide despite the shared template); reader images carry `data-reader-page-image`.
- **lagoonscans.com** is plain `PlainHTML` on Themesia's commercial "MangaReader" theme (same publisher as sushiscan's `ts_reader`), no Cloudflare. One series (`solo-max-level-newbie`, 259 chapters) exposes only its latest 6 both in static HTML and via the theme's own `action=get_chapters` ajax endpoint — a per-series data anomaly, not a site-wide cap; a shorter series lists all of them fine and is used for the smoke test.
- **toonily.com** is standard Madara behind a CF managed challenge, sharing the toongod/dragontea/manhuaus selectors. Its series URLs are `/serie/{slug}-{hash}/`, not the usual `/manga/{slug}/` — a guessed URL never returns a real page, so get the real one from the browse listing (`div.page-item-detail a`) instead of guessing the slug pattern.
- **Coin/premium paywalls are everywhere and mostly look like success.** Recent chapters commonly render with zero page images and no error (sanascans, rokaricomics, mistscans, ritharscans, violetscans, witchtoons), or list without a real `href` at all — en-thunderscans.com and elftoon.com put a `data-bs-toggle="modal"` in place of the link, so their `Rows` selectors end in `a[href]` to filter them out rather than yield chapters with bogus base-URL links. **Smoke-test with a chapter a bit behind the latest.**

### Sites that moved, or that we deliberately don't support

Sites rebrand and lock down constantly. Before declaring one dead, probe for a successor — and check the response *content*, since a 200 can be a parked or ransom page.

- **Moved, still supported**: tcbscans.com → tcbonepiecechapters.com; mangabat → mangabats.com; asuratoon → asurascans.com; zonatmo.com (taken down by Spanish police, Apr 2026) → zonatmo.org; aurorascans.com → qimanhwa.com → qimanga.com (same backend and paths, so just extend `Qimanga.Test()`'s regex); mangalivre.tv/.net (closure page) → mangalivre.to (stock Madara under a reskin, matched by `Tcb` with no new code); mangabuddy.com → mangak.io (`mangak.go`; the old domain now redirects to comizy.io, a different platform); witchscans.com → witchtoons.net (`witchtoons.go`); mangapark.to (CF 522s, origin down) and mangapark.io (parked) → mangapark.page, a live mirror — `mangapark.go` matches both `.to` and `.page` in case the former returns.
- **utoon**: utoon.net serves a static "developer invoice unpaid" hijack page (HTTP 200, no manga at all); the real site is a *different* domain, utoon.us, on a WordPress "mangaverse" theme (`utoon.go`). Always check for a same-branded-but-different domain before declaring a site dead.
- **colamanga** (#30) redirects to yoyomanga.com and now gates the reader behind their app (`APP观看该内容`) on top of client-side image encryption. Not feasible; unsupported.
- **comick.dev**: a visible browser clears its CF challenge and the harvested cookies do carry over to `api.comick.dev` (no code changes — `http/session.go` matches cookies by domain suffix), giving plain-HTTP access to the comic/chapter-list JSON. But the page-image endpoint (`/chapter/{hid}/get_images`) returns `[]` anonymously for every chapter tried, from obscure webtoons to Solo Leveling, and the live rendered reader receives no images either — matching manual browsing. Not supportable without an account.
- **sakuramangas.org** (#90): unsupported, and **the wall is the reader's client-side image decryption, not Cloudflare** (two July 2026 re-investigations got this wrong before — first blaming CF, then wrongly calling the reader "frozen"). Chapter listing works, and the first ~6 pages are plain JPEGs fetchable with the harvested session; pages past that batch 403 on their direct URL and exist *only* as `blob:` images their "AetherCipher" (`window.YggdrasilDecipher.decipher`) decodes **on genuine, dwelt human interaction**. After a fresh navigate the active page never decodes on its own (40s+ dwell → no `<img>`), and every automated arming recipe produced **zero** decoded images across pages 2–14. Doing it properly would mean reverse-engineering rotating obfuscated keys, 29×SHA-256 PoW headers and CSRF tokens — the exact stack that got the dedicated Tachiyomi/keiyoushi extension permanently delisted. Not worth it. Two genuinely reusable takeaways survived, though:
  - **CF clearance by attaching to a user-launched Chrome**: a real Chrome the user starts themselves with `--remote-debugging-port` (no debugger attached at challenge time) clears the managed challenge; chromedp then attaches over CDP (`chromedp.NewRemoteAllocator`, `ws://127.0.0.1:9222`) and reuses the cached `cf_clearance`, plus `page.BringToFront()` since attached tabs are backgrounded. It's our own chromedp-*launched* Chrome that CF detects, not headed mode per se — so this is the move for "works in my Chrome, not in automated Chrome".
  - **CDP `Input.dispatch*Event` produces `isTrusted:true` events**, which drive reader gestures that a page's JS refuses from synthetic `dispatchEvent`/`.click()` calls (those are `isTrusted:false` and ignored). Injected `Input.dispatchKeyEvent` ArrowRight/Left advanced sakura's reader cleanly 1→14; the site just additionally gates *decoding* on human-like dwell.

### Adding support for a new site

- If the site is plain HTML (chapter list + images in the reader page): add a `SiteSelector` entry to the list in `PlainHTML.Test()`, and add a smoke-test URL to the `grabber/html` makefile target and the README's supported sites list.
- If it needs a browser but the markup is selector-friendly: add a `BrowserSiteSelector` entry to `browserSelectors` in `plainhtmlbrowser.go`.
- Otherwise: create a new grabber implementing `Site` (embed `*Grabber`), register it in `IdentifySite()`, and add its own smoke target to the top-level `grabber:` aggregate (not `grabber/html`, which is for `PlainHTML` sites).

### Investigating/testing sites

- **Triage with curl before touching Go.** Fetch the manga page with a browser User-Agent and check the `<title>`: "Just a moment..." means a Cloudflare JS challenge and plain HTTP is out (same for TLS-level connection drops, empty-`<div id="app-root">` SPAs, or encrypted-image readers like colamanga). Don't burn time debugging the grabber in those cases.
- **Check response *content*, not just status/size, before escalating to a browser.** fanfox.net returns complete HTML with plain curl — no CF, no TLS block — but every series page, even for a non-mature title, is swapped for an age-confirmation interstitial (0 chapter rows) unless an `isAdult=1` cookie is sent; `http.SetCookie(...)` in `Test()` was enough, no browser needed.
- **403/500 in the app but 200 in curl almost always means headers.** `http/request.go` sends a browser User-Agent, Accept, Accept-Language, and referers with a trailing slash — all four exist because some site rejected requests without them.
- **Verify CBZ contents, not just their existence.** A run can "succeed" while producing empty or junk archives. Check that entries have non-zero sizes and real image magic bytes; `tools/verify-cbz` does this.
- **Smoke-test with recent chapters** — but not the newest. Some sites drop old content from their CDNs (inmanga 404s on early One Piece chapters) and MangaDex replaces licensed chapters with pageless external stubs, so "chapter 1" is often the worst target; the very latest chapter is frequently paywalled.
- **A near-empty `grep -o '<img src="..."'` result doesn't mean the images are JS-loaded.** rawkuma.net embeds every page as a plain `<img src='...'>` in the raw HTML — with *single*-quoted attributes, which a double-quote-only pattern misses entirely (goquery parses them fine). Confirm with a real HTML parser, or a quote-agnostic grep. Relatedly, `grep -c` on single-line minified HTML counts matching *lines*, not occurrences, so it hides second matches — use `grep -o | wc -l`.
- **A bare `h1` selector is often ambiguous**, even on a "real HTML" site: rawkuma has an earlier `<h1>` for a "Last Updates" sidebar label, sanascans has decorative stat labels. Scope it (`h1[itemprop="name"]`).
- **Chapter titles need `sanitizeTitle()` too.** Several themes pad `.chapternum` with raw tabs/newlines (violetscans, witchscans, en-thunderscans) or mix in a trailing date `<span>` (demonicscans); `parseChapterNumber`'s `\s*` tolerates it, but the whitespace was leaking into filenames until `PlainHTML.FetchChapters` started sanitizing chapter titles as well as the series title.
- **Use a temp dir namespaced to your own agent/worktree** (e.g. `/tmp/agent-<site>/`) when investigating. Generic scratch paths like `/tmp/series.html` collide across parallel agents and get silently overwritten mid-investigation — a file can change between two of your own commands with no edit of your own.
- The makefile is tracked as lowercase `makefile`: on macOS's case-insensitive filesystem editing `Makefile` works, but `git add` needs the lowercase name.
- macOS has no `timeout` command; use the Bash tool's timeout or a background-kill wrapper when running live-site smoke tests.
